# 태그 편집 개발·검증 계획

## 변경 경로와 영향

| 범위 | 개발 결정 | 확인할 결과 |
| --- | --- | --- |
| Free PostgreSQL | `tags.id`로 기존 행을 한 SQL 문에서 갱신한다. `book_tags`와 `tag_folder_tags`는 같은 ID를 참조한다. 아이콘 열은 기본 태그 아이콘으로 이관한다. | 기존 문서 수, 미분류 수, 복수 태그 폴더 소속, 태그 삭제 연쇄 동작이 유지된다. |
| 공용 API | 기존 목록·색상 API는 유지한다. 편집은 ID와 열었을 때의 이름을 검증하고 변경된 필드만 받는다. 이름 충돌은 409, 사라진 ID는 404다. | 중복, 연속 요청, 재생성된 이름, 잘못된 색·아이콘 요청에서 뜻하지 않은 병합이나 부분 저장이 없다. |
| 탐색 | 일반·폴더 안의 태그 행에 편집 버튼을 둔다. 이름이 바뀌면 활성 태그 주소를 교체하고 태그 기반 화면과 폴더 문서 캐시를 갱신한다. | 행 선택, 삭제, 태그 폴더 이동, PDF 드롭과 편집 버튼이 서로 섞이지 않는다. 열려 있는 같은 태그 페이지가 새 주소에서 같은 문서를 보여 준다. |
| 태그 표시 | 기존 색상 팔레트와 MUI 아이콘 선택지를 사용한다. 사이드바, 태그 페이지 제목, 인덱스 카드에 저장된 아이콘을 적용한다. | 키보드·터치로 버튼에 접근할 수 있고, 저장·취소·오류 상태와 기존 기본 아이콘이 확인된다. |
| 자동 분류 | 분류 어휘는 기존 공용 taxonomy를 따르고 이름이 바뀐 기존 연결은 ID로 보존한다. | 이후 자동 분류가 고정 어휘를 추천하면 원래 이름의 분류 태그가 새로 생길 수 있다. |
| Pro | 실제 저장소는 Google Sheets이며 이름에서 태그 ID를 유도한다. Free 저장소가 제공하는 편집 ID로 UI를 노출하고, 해당 기능이 없는 어댑터는 501을 반환한다. | Pro의 기존 태그 조회·색 변경 계약이 유지된다. |

## 실행과 기록

1. 패키지 빌드와 태그 라우트 테스트를 실행한다. PostgreSQL 통합 테스트는 `PDFIT_TEST_DATABASE_URL`의 전용 테스트 DB에서 실행하고 스키마를 정리한다.
2. Free를 `npm run deploy:standalone`으로 갱신하고 공개 바인딩, Docker health, 라이브러리 볼륨·API 응답을 확인한다.
3. 실행별 임시 태그와 폴더를 사용해 한국어 Playwright 시나리오를 실행한다. 편집 창의 `태그 아이콘` 그룹에서 이름과 도형이 서로 다른 버튼 48개 및 초기 선택인 `기본 태그`를 확인한다. 키보드로 `로봇`을 선택해 저장한 뒤 열린 두 탭, 새로고침, 사이드바, 태그 제목, 인덱스와 PDF 연결을 확인한다. 390×640 터치 화면에서는 편집 버튼을 누르고 마지막 선택지 `우주`를 저장한다. 취소와 중복 거부를 확인하고 임시 데이터를 정리한다.
4. API 상태, 테스트 로그, 테스트 정리 결과와 브라우저 스크린샷을 보고서에 남긴다. 행은 기존 `lnb-tag-row` / `lnb-folder-tag-row`에서 이름으로 한정하고, 편집 버튼·대화상자·입력·저장은 접근성 이름으로 찾는다.
