# 휴지통 문서 열기 실패 회귀 검증

## 환경

- Windows 11, 루트 Compose의 service 컨테이너, Chromium 브라우저
- Google Drive 원본 문서와 폴더는 변경하지 않는다.

## 단계

1. 폴더만 휴지통으로 이동한 Drive 변경 이벤트를 모의하고 `/api/folders/refresh`의 `folderDeletes`, `fileDeletes`, 시트 tombstone을 확인한다.
2. 문서가 없는 상태에서 북마크 조회 오류를 모의하고 HTTP 오류 응답 후 서버가 살아 있는지 확인한다.
3. 브라우저에서 404 문서 로딩을 모의하고 기술적인 ResponseException 대신 현지화된 안내가 표시되는지 확인한다.
4. 404 이후 서재 갱신 요청이 발생하는지 확인한다.
5. 패키지·서비스 빌드와 Docker 재빌드 및 건강 상태를 확인한다.
6. 폴더 문서 목록과 태그별 목록의 태그 열 너비·위치, 칩과 태그관리 간격을 Chromium에서 비교한다.
7. 보관함 빈 상태 안내와 부분 선택 시 전체 선택 체크박스 상태를 확인한다.
8. 활성 문서 하나의 로딩 게이지 및 첫 캔버스 시간을 관찰하고 느린 구간을 기록한다.

## 기대 결과

- 휴지통 폴더의 문서가 색인과 브라우저 캐시에서 제거된다.
- 문서 열기 실패가 서버 프로세스를 종료시키지 않는다.
- 문서나 폴더를 복원하거나 삭제하지 않는다.
- 두 목록의 태그 열은 같은 위치와 너비를 가지며, 태그 칩과 태그관리 사이 간격은 8px 수준이다.
- 빈 보관함 안내에 이전 명칭인 ‘북마크’가 나타나지 않는다.
