# 임베딩 스케줄 중첩 검증 계획

작성일 2026-11-28

격리 PostgreSQL 17과 pgvector에서 `embedding-rollover.test.mjs`를 실행한다. `PDFIT_TEST_DATABASE_URL`은 테스트 DB로 지정한다. 테스트마다 전용 스키마를 만들고 종료 시 제거한다. Free 브라우저 회귀는 별도 격리 컨테이너에서 실행한다.

| 조건 | 통과 기준 |
| --- | --- |
| 조회가 진행 중일 때 두 번 계획 | 신규 등록을 두 번 건너뜀. 기존 큐 확인 한 번 |
| 대기열 2,000건 모두 최신 리비전과 불일치 | 기존 자리에서 최신 리비전 처리 재개. 일부 공간이 나도 신규 등록 없이 변경 기록 보존 |
| ID가 낮은 원문 100건을 다시 수정 | 아직 확인하지 못한 다음 50건도 처리 |
| HTTP 응답 하나를 막은 동안 스케줄 3회, 같은 원문 2회 수정, 새 문서 삽입 | HTTP 최대 동시 요청 1건. 기존 작업은 최종 수정만 발행. 신규 문서는 큐가 빈 뒤 다음 주기에 색인 |
| `429` 뒤 스케줄러 교체 | 저장한 재개 시각 전 추가 호출 0건. 시각을 넘긴 뒤 기존 두 작업만 완료. 신규 작업은 큐가 빈 뒤 다음 주기에 등록 |

빌드는 `npm run build:pdfit`을 사용한다. Node 테스트 결과와 Docker health를 기록한다. 기존 `embedding-search-browser.mjs`에서 **의미 검색** 탭과 `semantic-search-results`로 긴 OCR 끝 문구를 확인하고, 공급자 쪽 요청 너비와 동시 요청 수를 `results.json`에 남긴다.
