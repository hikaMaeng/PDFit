# 태블릿 페이지 이동·태그 삭제 화면 검증

## 범위와 환경

- Windows 11, 루트 Compose `service` 컨테이너, `http://127.0.0.1:15201`.
- Playwright Chromium 터치 입력과 WebKit 터치 브라우저 시뮬레이션.
- PDF.js 및 PDFGPU 뷰어, 5페이지 합성 PDF, IndexedDB 태그 캐시 fixture.
- 실기기 iPad Safari와 공개 `pdfit.io` 배포는 이 계획의 검증 범위 밖이다.

## 절차와 합격 기준

1. `@pdfit/pdfit`와 `service`를 빌드하고 루트 Compose를 갱신해 healthy를 확인한다.
2. 저장된 두 페이지 보기로 태블릿 뷰포트(768×1024, 1024×1366)를 연다. 처음부터 두 페이지 모두 가로·세로 뷰포트를 넘지 않아야 한다. PC 100% 저장 배율은 그대로여야 한다.
3. `--touch-swipe`와 `--touch-swipe --gpu`에서 연속 스크롤을 끄고 한 페이지를 위·아래로 밀어 1→2→1, 두 페이지를 위로 밀어 1→3을 확인한다.
4. 다운로드 대화상자에서 터치·저장 선택기 미지원 브라우저의 폴더 저장 안내를 Chromium과 WebKit에서 확인한다. 일반 PC 다운로드 테스트는 그대로 통과해야 한다.
5. 태그 화면에서 전체 초기화와 현재 태그 단독 삭제를 각각 확인한다. 확인 문구는 “문서”여야 하고, 삭제 후 `/tag/...`가 아닌 기본 목록으로 이동해야 한다.
6. `git diff --check`를 실행하고 실패·제약·재현 명령을 보고서에 기록한다.
