# Book Bot page selection

Use a Free Docker fixture with a separate PostgreSQL directory, a loopback port and no external AI settings. Generate the synthetic books with `node apps/pdfit/tests/viewer-scan-browser.mjs --fixtures <books-dir>` and deploy the fixture with `npm run deploy:standalone`. Run the [integration test](../book-bot-page-selection.mjs) with `PDFIT_TEST_ORIGIN`, `PDFIT_TEST_PROJECT`, `PDFIT_TEST_CONTAINER` and `PDFIT_TEST_OUTPUT`. Use a Compose project named apart from the live service, with a `pdfit-bot-pages-` prefix.

- Open a session and check the title and full outline before any AI request.
- Activate the fixture embedding model and wait for the current source revisions to be indexed. Ask for chapter four. The first request contains the question, outline, dialogue and three tool definitions. The simulated model sends a structured tool call with fragmented arguments.
- Check that the current-book result ranks page 30 first, outside the chapter's outline interval. Both a different filename in the same folder and the same filename in a different folder have better vector matches. Neither appears in the result. The stale OCR at page 12 is also excluded.
- Resume a session with a stored summary. A dialogue-only question finishes in one request. Check that a follow-up can request shared-tag books, disambiguate a duplicate title, search another book and then answer. Verify ordered shared tags, original outline, matching tool IDs and a correctly scoped PDF page link.
- Check that the original question follows the reference JSON and stays intact across tool rounds. The stream carries final-answer fragments and retry returns the same saved turn.
- Make the fixture return raw model tool syntax split across chunks. Check for 502, zero answer deltas, and an unchanged revision. Restore a session with the old tool-only reply and verify that the browser shows the retry notice and the stored row stays intact.
- In headless Chromium, open the viewer with the **Bot** toolbar button, start a new chat, fill **질문** and click **질문 보내기** in the **Bot** dialog. Hold the tool response and an unclassified answer fragment. Capture the progress and the final reply after classification. Reload and confirm the saved reply.
- Run `node --test apps/pdfit/tests/ai-model-timeout.test.mjs packages/pdfit/tests/ocr.test.mjs` to check the shared queue, timeouts, follow-ups and prompt limits.
- Send a synthetic Korean chapter question through the configured APIBond model to check its retrieval JSON and answer stream. Record timing and ranges without uploading any library data.
- For an answer-quality change, ask for a summary and then ask why a specific design decision was made in the same chapter. Use the actual library's outline and indexed OCR on the configured local model. Replay the same page selection to compare answer formats with the sources held constant. Check that each answer directly addresses its request and grounds book-specific claims with page citations.
