# 태그 그룹 내비게이션 및 폴더 툴바 검증 계획

## 목적

사이드바의 서점형 태그가 의미 기반 그룹으로 구분되고, 폴더 상단 작업들이 기능군별로 시각적 위계를 가지는지 운영 Docker 화면에서 검증한다.

## 환경

- Windows 11
- root `docker-compose.yml`의 `service` 컨테이너
- Chromium, 1380×720 및 1024×768
- URL: `http://localhost:15202/folder/PDFit%20Library`

## 절차

1. 서비스 health endpoint가 200인지 확인한다.
2. 한국어 표시 언어를 설정하고 폴더 화면을 연다.
3. 사이드바에 소제목, 구분선, 그룹 사이 추가 간격이 없는지 확인한다.
4. 각 기존 태그가 한 번만 렌더링되고 의미 기반 순서로 이어지는지 확인한다.
5. 첫 태그를 클릭해 태그 상세 경로로 이동하는지 확인한다.
6. 폴더 화면으로 돌아와 보기 전환과 AI 일괄 태그가 노출되는지 확인한다.
7. 전체 선택·선택 삭제·보기 전환이 목록 제어행 안에 있고 AI 작업은 제목 행에 남는지 확인한다.
8. 전체 선택과 첫 PDF 행의 체크박스 열 정렬을 확인한다.
9. 전체 선택 시 선택 개수와 선택 삭제 활성 상태를 확인한다.
10. 선택 해제 문구를 눌러 모든 PDF 선택이 해제되고 삭제 버튼이 비활성화되는지 확인한다.
11. 목록/표지 아이콘으로 실제 렌더링 모드가 전환되는지 확인한다.
12. 폴더 태그 전체 해제 확인창과 폴더 범위 태그 연결 삭제를 확인한다.
13. 데스크톱 및 좁은 화면에서 가로 오버플로가 없는지 확인한다.
14. 브라우저 console error 및 page error를 수집한다.

## 합격 기준

- 알려진 태그는 의미 기반 순서로 연속 표시되고 사용자 태그는 목록 끝에 표시된다.
- 소제목이나 그룹 구분 장식이 없다.
- 폴더 작업과 목록 작업이 서로 다른 제어행에 배치된다.
- 전체 선택은 PDF 행 체크박스와 같은 열에 정렬된다.
- 그룹화로 인해 태그가 누락되거나 중복되지 않는다.
- 태그 탐색 기능이 유지된다.
- 툴바는 기능군 경계를 유지하며 화면 전체의 가로 오버플로를 만들지 않는다.
- 브라우저 오류가 없다.
