# 사이드바 "인덱스" 아이콘과 태그 인덱스 페이지

## 요구 기준 (사용자 요청 원문)

> 이 자리에 신기능인 인덱스 라는 아이콘이 들어간다.
> 누르면 전용 페이지에서 모든 태그의 도서가 나열된다.
> 그 스타일은 마치 썸네일 보기와 닮았으나 각 카드의 구성이 다르다.
>
> 1. 카드 상단에 태그 이름이 나온다.
> 2. 카드 내부에는 작은 폰트로 책제목이 나열된다. 책은 클릭하여 열 수 있다.
> 3. 태그가 소유한 책의 수는 제각각이라 핀터레스트 스타일의 타일이 될 수 밖에 없다.
> 4. (비어 있음 — 요청이 4번 항목 없이 끝났다)

"이 자리"는 요청에 첨부된 스크린샷의 빨간 상자, 곧 사이드바 태그 머리글 행에서 "태그" 글자와 오른쪽 합계 숫자(1319) 사이의 빈 곳으로 해석한다.

## 해석과 합격 기준

| 요구 | 합격 기준 | 확인 방법 |
|---|---|---|
| 이 자리의 아이콘 | 아이콘 버튼이 머리글 행 안에서 "태그" 글자 오른쪽, 합계 숫자 왼쪽에 있다. 누르면 머리글 접기 상태가 바뀌지 않는다. | 브라우저: 요소 좌표 비교, `aria-expanded` |
| 전용 페이지 | 아이콘이 `/tag-index`로 이동하고 현재 페이지 표시(`aria-current`)가 켜진다. | 브라우저 |
| 모든 태그의 도서 | 책이 있는 태그마다 카드 1장. 카드 수·순서·책 수·책 제목이 서버 API로 따로 만든 기대값과 같다. | 브라우저(기대값은 `/api/tags/summary` + 태그별 `/api/tags/:tag/books`) |
| 1. 카드 상단 태그 이름 | 카드 머리글에 태그 이름(h2), 누르면 `/tag/:name`. | 브라우저 |
| 2. 작은 폰트 책 제목, 클릭해서 열기 | 책 제목 글꼴 ≤ 12.5px. 제목 클릭이 해당 책의 `/viewer/...` 새 창을 연다. | 브라우저 |
| 3. 핀터레스트식 타일 | 카드가 2열 이상, 높이가 서로 크게 다르다(최대 > 최소×1.5). 가로로 넘치지 않는다. | 브라우저 |
| 썸네일 보기와 닮은 스타일 | 기계 판정하지 않는다. 스크린샷(`index-dark.png`, `index-light.png`)으로 눈으로 확인한다. | 스크린샷 |

범위 밖: 요구 4번(내용 없음), 미분류 카드(미분류는 태그가 아니다), 카드 안 책의 선택·삭제·태그 편집, 표지 썸네일 표시, Pro 배포.

## 절차

1. `npm run build:pdfit`(타입 검사 포함), `npm run deploy:standalone`(Free 컨테이너 재생성).
2. 라우트 테스트: `node --test packages/pdfit/tests/tag-index.test.mjs`(호스트).
3. PostgreSQL 쿼리 테스트: 같은 파일을 컨테이너 안에서 `PDFIT_TEST_DATABASE_URL`을 주고 실행(격리 스키마). 인덱스가 `listTagSummaries`·`listBooksByTag`와 같은 숫자·같은 책 목록인지 본다.
4. 브라우저: `PDFIT_TEST_CHANNEL=chrome node apps/pdfit/tests/tag-index-browser.mjs`
   - A(실제 라이브러리, 읽기 전용): 위 표의 카드 대조, 머리글 칩 문구·숫자, 사이드바 합계.
   - B: 아이콘 위치·동작, 다단 배치, 제목 클릭, 카드 머리글 클릭.
   - C: 390px 화면.
   - D(서버 응답 가로채기): 빈 상태, 오류 상태.
   - E: 다크·라이트 모드 글자 대비 4.5:1 이상.
5. 회귀: `untagged-browser`, `tag-unicode-order-browser`, `title-search-browser`, `npm run verify:repo`.
6. 컨테이너 `healthy`와 최근 로그의 error/fatal 확인.

## 합격 기준

- 위 표의 기계 판정 항목이 모두 통과한다.
- 카드 숫자 합, 머리글 칩, 사이드바 합계, API 합계가 서로 같다.
- 실행하지 못한 회귀 테스트는 이유와 함께 보고서에 적는다.
