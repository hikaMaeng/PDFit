# WebGPU 뷰어 배경색 검사

2026-11-27 작성.

## 환경

WebGPU를 사용할 수 있는 Chrome과 격리 Free Docker를 준비한다. 테스트 서재 `Fixture`에 같은 3쪽 PDF를 `fixture.pdf`와 `another.pdf`로 넣는다. 파일의 첫 쪽은 흰 종이 여백이 있으며, 양면 보기에서 두 쪽이 나란히 보여야 한다.

## 확인 순서

1. 새 브라우저 프로필에서 PDF를 연다. 상세 렌더링 후 종이 옆의 픽셀이 `#3a3a3a`인지 확인한다.
2. **배경색** 대화상자에 색 20개가 있고 어두운 회색이 선택됐는지 확인한다. 남색을 키보드로 선택하고 바깥 여백이 `#1e293b`로 바뀌는지 확인한다. 종이 픽셀, 스크롤 위치, PDF 요청 횟수를 비교한다.
3. 다른 탭의 PDF에서 남색 선택을 확인하고 모래색으로 바꾼다. 새로고침에도 색이 유지되고 원래 탭의 배경에 반영되는지 확인한다.
4. **이미지 조정**의 **야간**을 켠다. 종이 픽셀이 어두워지고 배경이 유지돼야 한다. 양면 보기에서 페이지 사이도 같은 배경색이어야 한다.
5. 폭 375px에서 팔레트를 열고 화면 안에 표시되는지 확인한다. 어두운 회색을 다시 고른다.
6. 스캔 문서에 가지색 배경을 적용하고 기울임 보정을 켠다. 보정된 종이 모서리 네 곳을 읽고 모두 흰색인지 확인한다.

## 재현

`PDFIT_TEST_ORIGIN`을 격리 주소로 설정한다. [배경색 검사](../viewer-background-browser.mjs)와 [기울임 보정 검사](../viewer-deskew-browser.mjs)를 실행한다. **배경색** 버튼과 대화상자는 역할과 이름으로 찾는다. 색의 선택 상태는 `aria-pressed`로 읽는다. `viewer status`와 `pdfgpu-page-shell`로 WebGPU 렌더링과 페이지 경계를 확인한다.

브라우저 버전, 화면 픽셀, 페이지 오류, 스크린샷을 저장한다. Docker 상태와 `/health` 응답도 기록한다.
