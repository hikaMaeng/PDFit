# 활성 태그 삭제 회귀 계획

2026-11-24 KST. Free Docker를 `npm run deploy:standalone`으로 갱신하고 `/health` 응답과 컨테이너의 라이브러리 볼륨을 확인한다.

한국어 브라우저에서 Free UI를 열고 API를 가로채 태그 한 개가 붙은 문서 한 권을 제공한다. 테스트별로 브라우저 저장소를 격리하고 실제 라이브러리에는 쓰지 않는다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 데스크톱에서 끝에 `/`가 있는 태그 URL을 열고 삭제 | 홈이 열리고 라이브러리와 인덱스 링크가 동작한다. 미분류 사이드바와 목록이 각각 1건을 표시한다. |
| 390px 터치 화면의 태그 폴더 안에서 현재 태그 삭제 | 홈에서 메뉴를 다시 열 수 있고 라이브러리, 인덱스, 미분류로 이동할 수 있다. |
| 삭제 응답을 보류한 사이 태그 인덱스로 이동 | 응답 이후에도 태그 인덱스가 유지되고 미분류 배지가 갱신된다. |
| 삭제 뒤 홈의 폴더 목록 조회가 503 응답 | 인덱스 링크는 사용할 수 있다. 홈의 다시 시도 버튼으로 목록을 받은 뒤 라이브러리 링크가 동작한다. |
| 삭제 API가 500 응답 | 오류가 표시되고 기존 태그 행과 경로가 복구된다. 미분류 배지는 0을 유지한다. |

`PDFIT_TEST_ORIGIN`, `PDFIT_TEST_CHANNEL`, `PDFIT_TEST_ARTIFACT_DIR`를 지정해 `node apps/pdfit/tests/tag-delete-active-browser.mjs`를 실행한다. 태그 행과 카운트는 `lnb-tag-row`, `lnb-folder-tag-row`, `lnb-untagged-count`로 찾고 삭제·홈 링크·다시 시도는 역할과 이름으로 찾는다. DELETE 횟수, 최종 경로, 페이지 및 콘솔 오류, 스크린샷을 남긴다.
