# Viewer comments

Run `node apps/pdfit/tests/viewer-comments-browser.mjs` with `PDFIT_TEST_ORIGIN` pointing to a disposable standalone library named `Viewer comments test library` containing `Fixture/Viewer comments.pdf` and `Other/Second book.pdf`. Use a three-page PDF for both. Set `PDFIT_TEST_ARTIFACT_DIR` to the screenshot and trace directory. The script seeds six comments and recognizes only its own earlier fixture notes on rerun.

- At 1280 px, open **Comments** from the PDF.js toolbar. Move the non-modal panel, resize it down to 320 × 300 px and grow it using its bottom-right handle. Scroll the body and navigate the PDF. A second book opens at the default size. Returning to the first book in PDFGPU restores both position and size.
- Open the same book with `engine=gpu`. Move the panel from its keyboard grip, open the second comments page, and save a Markdown post. Read it by its heading, table, checklist, and footnotes. Check the plain-text textarea and API body against the source, including a first-line indented code block and trailing newlines after editing. Close with **Close** and check toolbar focus.
- Open **Comments** on the cover card. Edit the same post in the textarea, save, and check the rendered delete confirmation. Cancel deletion, switch to the library list, and open **Comments** from the book row to check the saved post.
- At 390 px with touch input, open the PDF.js viewer and read the updated post. Move the floating window, then resize to 320 px. Verify that long code scrolls within the comment and the panel stays on screen. Capture evidence for both renderers, the cover, list, and touch layout.
- Use the **Comments** dialog and labeled buttons by role and accessible name. Use `book-comments-content` to measure scrolling and `viewer-comments-drag-handle` for pointer and keyboard drag. Keep the trace with the screenshots.
- Attach a PNG in the Markdown editor and check that it decodes, preserves aspect ratio, and fills the post width in the viewer, cover and list. Verify the book and post scope of the stored image route. Reject an SVG in both the picker and API. Save and delete an image-only post. Remove an existing attachment while retaining its Markdown and verify the removed asset returns HTTP 404.
- Resize with arrow keys and touch. In Arabic, verify that the popup has a single X at the upper right, a bottom-right resize handle, and Escape support.
- Check `/health`, Docker health, and container read access to both fixture PDFs before running the scenario.
