# 페이지·클립 텍스트(OCR) 브라우저 검증

## 요구 기준 (기능 계약 원문)

`packages/pdfit/docs/api.md` "OCR (local runtime)", `apps/pdfit/docs/usage.md` "Clip and page text (OCR)", 훅 목록 `apps/pdfit/docs/constraints.md`. 핵심 문장:

> `POST /api/ocr/page` `{ folder, filename, pageIndex }` (0-based) returns `{ text, source, cached, pageIndex, pageCount, durationMs }`.

> The `201` response carries `ocr.status: "pending"`.

> The page re-reads the list every 5 s while a clip is still being read, for up to 5 minutes.

> A digital page answers at once. A scanned page goes to the AI server and can take minutes; the dialog says so after 4 s. Results are kept per page until the PDF changes, so asking again is instant. Closing the dialog stops waiting, but the server still finishes and keeps the result.

## 대상과 전제

- 서버: 이미 배포된 Free 컨테이너 `pdfit-pdfit-1`, `http://127.0.0.1:15203`. 이 테스트는 배포·빌드·재시작·커밋하지 않는다.
- 브라우저: 설치된 Chrome headless(`PDFIT_TEST_CHANNEL=chrome`), Playwright 1.54.2. 언어 ko(`pdfit.language=ko`, `ko-KR`). 문구 기대값은 `packages/pdfit/src/front/i18n/messages.ts` ko 값.
- 디지털 PDF: `PDFIT_TEST_DIGITAL_FILES`(기본 `Git for Teams.pdf|인공지능을 위한 수학.pdf`) 순서대로 `POST /api/ocr/page`(pageIndex `PDFIT_TEST_DIGITAL_PAGE_INDEX`, 기본 49)를 물어 `source=text-layer`이고 공백 제외 200자 이상인 첫 파일.
- 스캔 PDF: `이북/Three.js로 3D 그래픽만들기.pdf`. pageIndex 20은 이미 캐시(vision). 캐시 안 된 페이지는 `PDFIT_TEST_SCANNED_UNCACHED_INDEX`(기본 30, 31쪽). 실행 전 `/app/data/ocr` 목록으로 캐시 여부 확인.
- 비전 대기 상한 `PDFIT_TEST_VISION_WAIT_MS`(기본 360000). 비전 요청은 서버에서 한 번에 하나라 3c 뒤에 4b를 돈다.
- 쓰기 제한: `POST /api/ocr/page`, 클립 만들기·지우기·다시 읽기, 번역 POST, 폴더 새로 읽기만 서버로 보낸다. 읽기 위치·뷰어 상태·주석 등 다른 비GET은 가로채 `{}`로 답한다(`blockedWrites`에 기록).
- 클립은 실제 경로로 만든다: 뷰어(PDF.js 엔진, 기본) 주석 도구 "선택 영역 보관"을 누르고 페이지 canvas 위를 마우스로 끈다(`PdfViewer/index.tsx` `handleCapturePointerUp` → `POST /api/bookmarks/:folder/:filename`, PNG).

## 합격 기준

| 단계 | 합격 기준 | 기대값의 출처 |
|---|---|---|
| 2 디지털 PDF | 후보 중 text-layer 파일 하나를 고르고 탐색 결과 전부 기록 | `POST /api/ocr/page` |
| 3a 디지털 페이지 | 페이지 번호 칸으로 50쪽 이동, `page-ocr-open` 접근 이름 "페이지 텍스트 읽기", 대화상자 제목 "50페이지 텍스트", 요청 pageIndex 49, 패널 `done`·`data-source=text-layer`, 글 = 같은 페이지 API 글, 복사 버튼(클립보드 = 글), 소요 시간 `n.n s` | API 응답 |
| 3b 스캔 캐시 페이지 | 21쪽: `done`, `vision`, 응답 `cached=true`, 4 s 전에 끝나 느림 안내 없음, 글 = API | API 응답 |
| 3c 스캔 캐시 안 된 페이지 | 31쪽: 8 s 안에 끝나지 않음, 느림 안내 3.5~6 s 사이 표시, 닫고 다시 열면 pending에서 다시 시작, 끝내 `done`·`vision`, 글 = API(이제 `cached=true`). 시간 초과·실패면 그 상태와 문구를 그대로 기록 | API 응답 |
| 4a 디지털 클립 | 마이클립 탭을 먼저 연 채 뷰어에서 클립 생성: 201, `ocr.status=pending`. 마이클립 배지가 새로고침 없이 pending → done, 서버 `source=text-layer`, 클립 글의 줄마다(공백 제거) 그 페이지 글 안에 있음, 대화상자 글·출처 = 서버, 다시 읽기 202 → pending → done | `GET /api/bookmarks`, 3a 페이지 글 |
| 4b 스캔 클립 | 21쪽 클립 뒤 마이클립을 열면 배지 pending, 폴링으로 done·vision(또는 failed/unavailable 그대로 기록), 대화상자 글 = 서버 | `GET /api/bookmarks` |
| 5 다크·375 px | 다크 1440 px와 375×812 모바일에서 대화상자 제목·done·글 = API, 대화상자가 화면 안, 페이지·글 상자 가로 넘침 0 | 렌더 좌표 |
| 폴링 | 마이클립 탭 `GET /api/bookmarks` 시각과 간격 기록(계약 5 s) | Playwright `request` |
| 정리 | `finally`에서 만든 클립을 DELETE, 최종 `GET /api/bookmarks` id 집합 = 시작 집합 | 시작 시점 목록 |

PDF를 지우거나 옮기거나 올리거나 태그를 바꾸지 않는다. `/api/covers`를 부르지 않는다.

## 절차

1. `docker ps`로 `pdfit-pdfit-1` healthy, 배포 번들에 `page-ocr-open`·`clip-ocr` 있는지, `/app/data/ocr` 캐시 목록, 시작 클립 수 기록.
2. `PDFIT_TEST_CHANNEL=chrome PDFIT_TEST_RUN=<YYYYMMDD_HHMM>_ocr node apps/pdfit/tests/ocr-browser.mjs`.
3. 실행 뒤 `GET /api/bookmarks` 수가 시작과 같은지 확인.

증거: `apps/pdfit/tests/reports/ocr/<run>/`(`result.json`, 스크린샷). 보고서: `apps/pdfit/tests/reports/ocr/<YYYYMMDD_HHMM>.md`.
