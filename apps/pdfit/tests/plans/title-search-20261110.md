# 책 제목 검색 계획

## 요구 (사용자 지시 원문 요약)

- 좌측 메뉴 상단에 검색창과 버튼을 고정한다.
- 검색은 책 제목만 대상으로 하고 부분 문자열을 허용한다.
- 검색 시에는 별도의 검색 결과 리스트 페이지가 필요하다.
- 검색은 파일 시스템 기준이 아니라 DB 기준이다.

## 환경

- Windows 11, Docker Compose `pdfit`(Free, 포트 15203), 내장 PostgreSQL 17, 이북 폴더 PDF 719권
- 브라우저: 설치된 Chrome(헤드리스), `PDFIT_TEST_CHROMIUM_PATH`
- DB 통합 테스트: 일회용 `pgvector/pgvector:pg18` 컨테이너

## 절차

1. `packages/pdfit/tests/title-search.test.mjs` 라우트 계약: 질의 전달·`total`/`books` 응답, 빈 질의·201자 질의 400, 검색 미구현 저장소 501.
2. 같은 파일의 PostgreSQL 테스트(`PDFIT_TEST_DATABASE_URL`): 한글/영문 부분 문자열, 대소문자, `%` `_` 리터럴, NFD 파일명, 확장자·폴더명·태그 비대상, `limit`과 `total` 분리.
3. 배포된 서버의 `/api/search/books`를 실제 DB로 호출해 건수를 기록한다.
4. `apps/pdfit/tests/title-search-browser.mjs`: 검색창 위치(스크롤 영역 밖)와 스크롤 후 불변, 빈 입력 시 버튼 비활성, 버튼·Enter 제출, 결과 건수가 API와 같은지, 모든 결과 제목에 검색어 포함, 표지 보기 읽기 전용, 결과 없음·검색어 없음 문구, 폴더 페이지에서의 검색, 390px 드로어 닫힘, 콘솔 오류 없음.

## 실패 기준

- 결과 건수가 DB 검색 API와 다르거나 제목에 검색어가 없는 책이 섞임
- 폴더명·태그만 일치하는 책이 검색됨
- 사이드바를 스크롤하면 검색창이 움직임
- 콘솔·페이지 오류

## 초성 검색 추가 (2026-11-10)

- 요구: `books`에 초성 제목 필드를 두어 전체 레코드를 채우고, 폴더 새로고침·파일 추가 등 테이블 갱신 코드가 초성 필드를 만들게 하며, 검색은 초성 필드와 제목 필드를 동시에 본다.
- 절차: (1) `titleChoseong` 단위 검사 (2) 일회용 PostgreSQL에서 `syncBooks` 기록·NULL 백필(`book_tags`에서 보충된 행 포함)·재동기화 복원·초성/공백/혼합 검색·완성형 검색어 오탐 없음 (3) 배포 DB에서 NULL 0건, 값을 일부러 어긋나게 한 뒤 `POST /api/folders/refresh`로 복원되는지 (4) 브라우저에서 초성 검색 건수를 API·폴더 파일 목록 기반 독립 계산과 비교.
- 실패 기준: 백필되지 않은 행이 남음, 새로고침 후 값이 어긋남, `자바`가 초성이 같은 `정보`에 일치, 건수가 독립 계산과 다름.
