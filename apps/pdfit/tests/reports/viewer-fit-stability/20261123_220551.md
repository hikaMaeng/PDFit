# Test Report: Viewer fit stability

2026-11-23 22:05 KST. Windows, Chromium 158.0.8127.18, Free Docker service at
`http://127.0.0.1:15203`. The regression uses synthetic PDFs and intercepts API
requests. Chromium shows classic scrollbars for this test.

## Observed results

| Action | Before (CSS px) | After (CSS px) |
| --- | --- | --- |
| Fit Width | Alternated between 1352 and 1344 | 1344 once |
| Fit Height | Alternated between 864 and 856 | 856 once |
| Resize with width fit | Multiple sizes | 1264 once |
| Open bookmarks with width fit | 1044 then 1052 | 1044 once |
| Resize with height fit | Multiple sizes | 776 once |

Both baseline fits oscillated during the one-second observation. On the fixed
build all five actions matched the available axis within 1 CSS pixel and the
regression recorded no browser console or page errors. The Korean accessible
button names and the two test IDs specified in the plan resolved uniquely.

## Additional verification

- `pdf-zoom-acrobat-browser.mjs` passed at 100%, 125%, Fit Width, and Fit Height.
- `viewer-double-fit-height-browser.mjs` passed its desktop, tablet restore
  (`--large-tablet`), and touch swipe (`--touch-swipe`) scenarios with PDF.js
  and with `--gpu`. The existing PDFGPU test adds the WASM CSP allowance via
  route interception.
- Display-scale, PDFGPU integration, and spread-pairing tests passed 17/17.
- `npm run deploy:standalone` from a checkout with this patch and the original
  Free data mounts built and recreated the container. Docker reported
  `healthy`, `/health` returned `ok`, and the container found 731 library PDFs.

## Reproduce and inspect

Run `node apps/pdfit/tests/viewer-fit-stability-browser.mjs` against the test
origin. Set `PDFIT_TEST_OUTPUT` to retain separate baseline and fixed runs.
The recordings are under `test/20261123/viewer-fit-stability/{before,after}/`
with `result.json`, `fit-width.png`, and `fit-height.png` in each directory.
The Free test does not exercise the hosted Pro service.
