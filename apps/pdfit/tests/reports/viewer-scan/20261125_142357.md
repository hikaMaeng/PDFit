# Viewer scan coverage verification

2026-11-25 14:23 KST. Tested the scan coverage change with viewer baseline `4709371` in an isolated Free Docker instance at `http://127.0.0.1:15353`. [Test plan](../../plans/viewer-scan-20261124.md).

| Check | Result |
| --- | --- |
| Build and Docker | `npm run deploy:standalone` completed in 65.4 s. Both builds passed. The container was `healthy` with zero restarts, `/health` returned HTTP 200, and all three mounted fixture PDFs were visible and indexed. |
| Desktop and mobile toolbar | Chrome showed **Scan → 20% → start page → Start** on desktop. The percentage used a smaller font than the input and Start button. At 320 px the scan controls fit and the toolbar had no horizontal overflow. |
| Saved-page coverage | PDF.js showed 20% for pre-existing text, 60% while another vision request was held, and 80% after finishing a scan that began on page 2. The GPU viewer showed 0% on a fresh document and 25% after cancellation. The failure fixture showed 33% after one of three pages was saved and 100% after retry. |
| Regressions | The Chrome smoke and full scan scenario passed with zero browser page errors. The smoke recorded zero console errors. The mock vision endpoint received six image requests with peak concurrency 2. Nine OCR tests passed. |
| Locale resources | The new accessible label has 12 translations. `Intl.NumberFormat` uses zero fractional digits for percentages in all 12 locales. The generic i18n check reported the same eight pre-existing `AIServersTab.tsx` findings before and after the change. |

The first scenario expected 40% after the first vision response. The embedded-text tail also saved before the next document received a vision slot. The revised scenario confirms those saved pages via the API and checks 60% while the remaining vision request is held. It passed on a fresh database and again after integrating `4709371`. The server logged the injected HTTP 502 and the expected failure for an image page with no vision server configured.

The scenario used the Korean accessible names for the coverage meter, scan button, spinbutton and Start button, and used `viewer-outline-open` for Contents.
