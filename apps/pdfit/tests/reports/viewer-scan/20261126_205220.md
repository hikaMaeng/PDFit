# Free OCR concurrency change after a live timeout

2026-11-26 KST. [Test plan](../../plans/viewer-scan-20261124.md).

- At 18:23:01, page 34 of a 404-page PDF failed in `vision-response` with `TimeoutError`. The model endpoint had returned HTTP 200, and the response body hit the 1,200,000 ms deadline. The job drained and finished with 45 processed pages.
- At 20:52:20, `PATCH /api/settings/ai-servers/707` returned HTTP 200. A separate GET read back `ocrConcurrency: 4` for `local-qwen36`, previously 8. No service recycle was needed.
- The first restart attempt hit an 8-second PDF lookup failure and ended in `prepare-document` with `source-changed`. The mounted library then served a direct file read with a `%PDF-` signature, and `GET /api/ocr/scan/pages` returned the same 45 indexed pages. Page 34 was the only missing page through 46.
- At 20:53:29, a retry from page 1 reused the 45 indexed pages and saved page 47. Its logs showed `concurrency: 4` and `visionLimit: 4` with four active model requests. At 20:58:18 the job was running with 46 indexed pages and page 34 still in `vision-response`.
- Docker reported `healthy` with zero restarts. The Free loopback endpoint on port 15203 returned HTTP 200 from `/health`. The live change used the Settings and Scan APIs. The viewer was unchanged.
