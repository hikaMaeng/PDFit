# 사이드바 태그 유니코드 순 정렬 결과

계획: `apps/pdfit/tests/plans/tag-unicode-order-20261110.md`

## 원인

`packages/pdfit/src/front/layout/LNB.tsx`의 `orderedTags`가 `bookstoreTagGroupFor`로 서점 분류 그룹을 먼저 배치한 뒤 문서 형식, 사용자 태그 순으로 이어 붙이고 있었다. 그 결과 `데이터베이스, 프로그래밍, 마케팅, 디자인, …, AI, API …` 순서가 되었다.

## 변경

- `orderedTags`를 `[...tags].sort`로 바꿔 이름의 UTF-16 코드 유닛 순으로만 정렬한다. 그룹화와 관련 import를 제거했다.
- `packages/pdfit/docs/usage.md`의 사이드바 정렬 설명을 갱신했다.
- `tag-grouped-navigation-browser.mjs`의 기대 순서를 유니코드 순으로 갱신하고, `# ` 접두 때문에 이미 어긋나 있던 이름 추출식과 첫 행 의존 단언을 고쳤다.

## 실행

- `npm run deploy:standalone` 성공(이미지 재빌드, `pdfit-pdfit-1` 재생성, 라이브러리 인덱스 719 PDF/2 폴더). 이후 `pdfit-pdfit-1`은 `Up (healthy)`, `GET /` 200.
- `node apps/pdfit/tests/tag-unicode-order-browser.mjs` — **PASS**, 태그 25개, 첫 항목 `3D그래픽`, 마지막 `프로그래밍`, 브라우저 오류 0건.

## 미해결·범위 밖

- `tag-grouped-navigation-browser.mjs`는 정렬 단언(119~124행)까지는 통과하지만 이후 `태그 전체 초기화` 버튼 단계에서 타임아웃으로 실패한다. 이번 변경과 무관한 기존 불일치이며 수정하지 않았다. 정렬 검증은 새 전용 테스트가 맡는다.
- Pro(`pdfit-service-1`, 15202)는 비공개 체크아웃 배포 경로라 이번에 재배포하지 않았다. 공유 패키지 변경이므로 Pro도 다음 배포 때 반영된다.
- 사용자 화면의 실제 라이브러리(태그 연결 합계 1319)가 아닌 모킹 데이터로 검증했다.
