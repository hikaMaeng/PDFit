- 환경: Windows 11, Docker Desktop, 로컬 Compose `service` healthy,
  Playwright Chromium/WebKit
- 배포본: `release/pdfit-service-0.4.4-light-viewer-20261001-private-lan-windows-amd64.zip`

## 절차와 결과

1. `npm run build --workspace @pdfit/pdfit`, `npm run build --workspace service`,
   `docker compose up -d --build --wait --wait-timeout 60 service`: 통과.
2. `node apps/pdfit/tests/viewer-light-canvas-browser.mjs`: PDF.js Chromium
   라이트·다크 통과.
3. 같은 테스트의 `--webkit`: PDF.js WebKit 라이트·다크 통과.
4. 같은 테스트의 `--gpu`: PDFGPU Chromium 라이트·다크 통과. 이 테스트는
   응답의 CSP에 `wasm-unsafe-eval`을 테스트 중에만 허용했다. 운영 CSP는
   변경하지 않았다.
5. 한 페이지에서 두 페이지 및 연속 스크롤로 전환해도 작업 영역 배경은
   라이트 `rgb(232, 241, 248)`, 다크 `rgb(58, 58, 58)`으로 유지됐다.
   북마크 패널은 라이트 `rgb(244, 249, 253)`, 다크
   `rgb(36, 36, 38)`이었다. 스크린샷을 확인했고 페이지 오류는 없었다.
6. 새 Docker 이미지에서 배포 ZIP과 같은 이름의 압축 해제 폴더를 만들었다.
   ZIP SHA-256 `D71E84815DDA5DE014AD44AA3B48599564B4D111DEA9883A41CD7E0256454D8B`,
   내부 이미지 SHA-256 `7746B2B803EFD22A2450FA07B8CE662EED3C1638A7C1CD17DB5EEDA2104B7924`가
   각각 `.sha256`, `SHA256SUMS`와 일치했다.
7. ZIP에는 Docker 이미지, `.env`, 설정 파일, Compose, Caddyfile,
   설치·로그·중지 스크립트, README, 빈 `data`가 있다. 확인한 민감 설정
   9개는 모두 비어 있으며 데이터 폴더에는 `.gitkeep`만 있다.
   `docker compose config --quiet`와 `git diff --check` 통과.

## 실패와 한계

- 첫 PDFGPU 테스트는 운영 CSP가 WASM 컴파일을 거부해 기본 PDF.js 뷰어로
  자동 전환되면서 실패했다. 테스트 응답에만 `wasm-unsafe-eval`을 허용하니
  PDFGPU의 라이트·다크 색상 검증은 통과했다. 운영 CSP 문제는 이번 색상
  작업의 범위 밖이며 변경하지 않았다.
- 패키지 설치 실행은 `.env`에 Google OAuth 값이 없어 수행하지 않았다.
  실제 다른 컴퓨터에서의 설치와 공개 사이트 배포는 미검증이다.
