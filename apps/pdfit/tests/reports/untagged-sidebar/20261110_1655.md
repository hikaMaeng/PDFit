## 기각된 가설

- 브라우저 A의 첫 실패("미분류 뒤에 실제 태그가 있어야 한다")는 구현 결함이 아니라 태그 요약이 비동기로 늦게 도착한 타이밍 문제였다(로드 대기 후 통과).
- 두 번째 실패("실제 태그 페이지에서는 미분류가 선택 해제")도 URL 변경 직후 React 재렌더 전에 클래스를 읽은 경합이었다(대기 후 통과, 선택 상태가 잘못 남는 결함이 아님).
- 처음에 미분류 행에 `.pdfit-tag-row` 클래스를 붙였으나, 기존 테스트 6개가 이 클래스로 실제 태그 행을 센다. 그대로 두면 `tag-unicode-order` 등이 깨질 수 있어 클래스를 제거하고 별도 `data-testid`로 구분했다.

## 한계

- 브라우저 B는 서버의 태그 추가 응답을 가로챘다. 실제 DB에 태그를 쓰는 경로(미분류에서 태그를 붙여 실제로 목록에서 빠지는 것)는 PostgreSQL 쿼리 테스트(격리 스키마)로만 간접 확인했고, 실제 라이브러리 문서에는 쓰지 않았다.
- 하이드레이트된 브라우저 캐시 경로(`listCachedUntaggedBooks`, Pro 런타임이 사용)는 타입 검사만 통과했고 실행 검증하지 않았다. Pro는 배포하지 않았다.
- 배포 이미지는 작업 트리에서 빌드했다. 당시 작업 트리에는 다른 세션이 진행 중이던 초성 검색 변경(`postgres/index.ts`, `metadataCache.ts`, 미추적 `shared/choseong.ts`)이 함께 있었다. 커밋에는 이 기능의 변경분만 담았다.
- 목록 보기와 표지 보기 중 목록 보기만 화면 검증했다(표지 보기는 같은 `TagPage` 렌더를 공유하며 이번에 바꾸지 않았다).
- 이 PC에는 Playwright 번들 Chromium 빌드가 없어 시스템 Chrome 채널로 실행했다.
