# Viewer text selection

The Free Docker viewer passed the text selection scenario at 19:27 KST on
2026-11-27. The final standalone deployment took 83.230 seconds and served
`viewer-jDJ7nkAh.js` on port 15203. Docker marked the container healthy.
Both published addresses returned HTTP 200 from `/health`. The container
could read the mounted library, and the refresh indexed 744 PDFs across
two folders.

## Browser results

Windows Chrome 158.0.8127.89 ran the
[scenario](../../viewer-text-selection-browser.mjs) at
`http://127.0.0.1:15203`. The browser supplied a two-page digital PDF and a
raster-only PDF. No library or annotation writes were sent.

| Check | Observed |
| --- | --- |
| Default text selection | Drag and Ctrl+C copied native text. No OCR assets loaded. |
| Left toolbar | The Freehand drawing button cleared the range and disabled text selection. Pressing it again restored selection. |
| Navigation and zoom | Copy worked after zoom and after moving to the next page. |
| Raster-only PDF | An English line, a range across two lines, and the Korean word 한글 copied with their expected spaces and newline. |
| Touch | A Chromium touch hold selected 한글. Pressing **Copy text** copied it. |
| Network | The worker, WASM core, and both language files loaded from the viewer origin. There were no external requests and no unhandled page errors. |

The two HTTP 404 responses came from `/api/ocr/scan/pages` for the
synthetic books, which are absent from the library. The scenario found
the viewport and text pages by test IDs and used exact button labels and
fixture text for interactions.

The first Docker run exposed a Tesseract.js initialization error with
in-memory language descriptors. The final run used the versioned model
files served by PDFit. The touch test initially produced no native
selection in desktop Chrome's touch emulation. The viewer now selects the
word and supplies a copy button after the hold when needed.

## Regression and scope

- Node tests passed 34 cases across viewer text selection, OCR, annotation
  coordinates, PDFGPU integration, and spread pairing.
- `npm run verify:release-contract` passed for PDFit 0.4.25 and PDFGPU 0.1.16.
- The repository i18n check still flags eight existing lines in
  `AIServersTab.tsx`. The copy button uses the existing localized label.
- The browser test used a single-block scan. Multi-column scan order,
  a physical Galaxy device, and the Pro runtime were outside this run.
