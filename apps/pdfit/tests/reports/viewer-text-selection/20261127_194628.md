# Korean OCR clipboard spacing

The Free viewer copied the heading and the three printed lines below it on
the reported PDF's page 175. Chrome copied the heading with a line break
and the body as one paragraph. The clipboard matched the expected text
across all 78 selected OCR boxes.

Before the fix, the same section split Korean words into syllables and
inserted line breaks inside the paragraph. Copy now compares gaps between
OCR boxes to recover word boundaries. It uses the line margin, height, and
vertical distance to recognize wrapped prose. The unit cases also cover
headings, code lines, and a standalone short Korean word at a wrap.

The Free container built and restarted with `npm run deploy:standalone`
on 2026-11-27. The run took 105.143 seconds. Docker health was healthy and
both published addresses returned HTTP 200. The library refresh indexed
744 PDFs across two folders.

Windows Chrome 158.0.8127.89 verified the real PDF and the existing
[viewer scenario](../../viewer-text-selection-browser.mjs) on port 15203.
The scenario exercised native text, scanned text, toolbar switching,
navigation, zoom, and emulated touch copy. The two scan status 404s belong
to the synthetic books outside the library. Node tests passed 37 cases and
the release contract passed. No Pro run or real Galaxy run was performed.
Complex layouts and ambiguous Korean wraps still depend on OCR quality.
