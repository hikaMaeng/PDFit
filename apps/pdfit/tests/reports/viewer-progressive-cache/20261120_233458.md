The [release contract](../../../../../release-contracts/pdfit/v0.4.9.json) pins PDFGPU source `8fcc221743031b73378df6732f9d5633a0e81fb7` and its tarball digest. ## Build and runtime

- PDFGPU build passed in all four workspaces and `npm run test:libs` passed 79/79.
- PDFit `npm run test:pdfgpu` passed 14/14. `npm run verify:repo` and all four PDFit workspace builds passed, including the Pro build.
- `npm run deploy:standalone` completed in 68.254 s and refreshed the index to 719 PDFs across two folders. The new Free container ran 0.4.9, reported `healthy` with zero restarts, and could enumerate 719 PDFs under `BOOKS_ROOT`. `/health` returned HTTP 200 on loopback and the LAN binding at port 15203.

## Browser

- The Free root smoke passed. The [scenario](../../plans/viewer-progressive-cache-20261120.md) then exercised the deployed viewer with a synthetic 96-page PDF fulfilled by a browser route. API writes were intercepted.
- The **viewer controls** toolbar's **Page number** field jumped from 3 to 80. One run issued the uncached preview request after 11.5 ms and received it after 21.8 ms. The first detail request came after 215.4 ms. Directional prefetch began after 512.8 ms with pages 79 and 81 and reached page 83.
- **viewer status** reported WebGPU and showed page 81 at preview quality after navigation. The **PDF viewer** region had the expected page color, and the trace contained only the prefetch request for page 81. The 80 and 81 center pixels matched their distinct fixture colors. There were four PDFium workers and zero page errors.
- The existing `pdfgpu-0110-viewer-browser.mjs` regression passed 13 checks on a 12-page library PDF. It verified four PDFium workers, canvas output, focused and unfocused PageDown, and spread pairing in both viewers. It blocked 20 writes and observed zero page errors.
- In the first fixture run, page 8 was cached before navigation. A longer fixture and a jump to page 80 made the uncached case reproducible.
- Local evidence is under `test/20261120/233329_headless-browser-test/`, `test/20261120/viewer-progressive-cache-webgpu/`, and `test/20261120/viewer-progressive-cache-library/`.

## Boundaries

The measured times are from one synthetic PDF in desktop Chrome. Pro was built locally. Runtime deployment and browser scenarios were on Free. The default PDF.js path uses HTTP range loading. The GPU scheduling path is selected with `engine=gpu`.
