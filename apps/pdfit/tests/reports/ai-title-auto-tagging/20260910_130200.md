# Folder-wide AI tag persistence repair

- Timestamp: 2026-09-10 13:02 KST
- Environment: Windows 11, Docker Desktop, Chromium/Playwright
- Runtime: `pdfit-service-1`, ports 15201 and 15202

## Reproduction evidence

The service log from the reported run contained one successful request for `블링크.pdf` and 47 HTTP 502 responses. The former browser implementation issued up to three independent requests concurrently, and every book performed repeated Google Spreadsheet reads and appends. This exhausted or collided with the metadata write path, leaving only the first successful book visible.

## Repair

1. Replaced the browser-side per-book request loop with one folder-wide API request.
2. Added bounded server-side title classification followed by one metadata batch containing every successful tag and PDF relation.
3. Added transient Google metadata retries to the service metadata router.
4. Kept successful classifier results and explicit per-book error reporting.

## Verification

1. Shared route integration: 6/6 passed, including two books persisted through exactly one `addTags` call.
2. Service metadata mutation and bookmark route suite: 14/14 passed, including multiple tags persisted through exactly one Spreadsheet append.
3. Browser automation: per-book action, dialog action, folder-wide confirmation, completion notification, and rendered tags passed.
4. Shared runtime parity: 198 files verified.
5. Service and local production builds: passed.
6. Docker image rebuilt and `pdfit-service-1` recreated successfully.
