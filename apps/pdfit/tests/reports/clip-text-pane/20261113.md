## 원인 확인 (변경 전)

- 클립은 1개(`2b012952…`, `인공지능을 위한 수학.pdf` 29쪽, 2026-11-10 저장). `GET /api/bookmarks`의 `ocr`이 `null`이었다.
- OCR 기능(커밋 `d3872fe`)보다 먼저 만든 클립이라 OCR 큐에 들어간 적이 없다. 재시작 때 다시 계획하는 대상은 `ocr_status = 'pending'`인 클립뿐이라 `null`은 영영 읽히지 않는다.
- 화면(`BookmarkPage.tsx` `clipOcrState`)은 `ocr`이 `null`이면 패널을 그리지 않았고, 읽기를 시작할 버튼도 없었다. 다시 읽기 API `POST /api/bookmarks/:id/ocr`은 이런 클립도 받는다.

## 변경

- 모달 아래쪽 버튼 줄에 "텍스트 보기"(`bookmark-preview-text`, `aria-expanded`). 누르면 모달이 `lg`로 넓어지고 클립 옆(좁은 화면은 아래)에 "클립 텍스트" 창(`clip-text-pane`, 닫기 버튼)이 열린다. 다시 누르면 "텍스트 닫기".
- 창 안: OCR이 있으면 기존 `OcrTextPanel`(선택 가능한 글, 출처, 복사, 다시 읽기). 없으면 "이 클립은 아직 텍스트를 읽지 않았습니다." + "텍스트 읽기"(`clip-ocr-read`).
- 모달 아래쪽에 있던 OCR 패널은 옆 창으로 옮겼다. 기존 `ocr-browser.mjs`는 버튼을 누른 뒤 패널을 읽도록 고쳤다(재실행하지 않음).

## 관찰

- 이 클립의 글은 PDF 자체 텍스트 층에서 왔고(`text-layer`), 품질이 낮다. 예: "인공지능빼서는 01렇게 팔용한다", "신경밍'1l euraln e two d". 스캔본에 들어 있던 낮은 품질의 숨은 텍스트 층으로 보인다. 지금 규칙은 텍스트 층에 글자가 하나라도 있으면 AI 비전을 부르지 않는다. 이번 범위에서는 바꾸지 않았다.
- 같은 체크아웃의 다른 작업이 남긴 미커밋 변경(`packages/pdfit/src/front/pages/SearchPage.tsx`, `packages/pdfit/src/front/components/useBookLibraryActions.tsx`)이 배포 빌드에 함께 들어갔다. 이 커밋에는 넣지 않았다.
