# 스캔본 목차 복구와 로딩 재시도

2026-11-28 00:11 KST. [테스트 계획](../../plans/viewer-outline-loading-20261128.md).

## 서재의 책

로컬 Free `http://127.0.0.1:15203`에서 `에이전틱 디자인 패턴.pdf`를 열었다. 508쪽 PDF에는 내장 목차가 없었고 처음 11쪽과 마지막 2쪽에서 추출할 텍스트가 없었다. 복구 전에는 저장 목차와 YES24 조회 모두 404였고 목차를 누른 뒤 6,144ms에 실패 안내가 떴다. 파일명과 [YES24 등록 제목](https://www.yes24.com/product/goods/193850555)의 표기가 달랐다. [복구 전 브라우저 결과](../../../../../test/20261128/outline-loading-before/result.json).

PDF 7–12쪽의 인쇄 목차에서 부, 29개 장, 앞뒤 항목을 옮겼다. 39개 항목 모두 시작 쪽의 제목을 확인한 뒤 `If-None-Match: *`로 저장했다. 다시 조회한 목록과 등록 데이터가 일치했다. 브라우저는 목차를 194ms에 열었고 1장, 10장, 29장을 누르면 각각 PDF 44, 202, 494쪽으로 이동했다. [브라우저 결과](../../../../../test/20261128/outline-loading-book/browser.json) · [목차 화면](../../../../../test/20261128/outline-loading-book/viewer.png).

## 응답 지연 시나리오

별도 워크트리 `6aea40d`에 목차 수정만 적용하고 `npm run deploy:standalone`으로 Free `http://127.0.0.1:15237`을 띄웠다. 최종 배포는 70.366초 걸렸다. 두 워크스페이스 빌드와 `/health` 200을 확인했고, Docker는 시작을 마친 뒤 `healthy`였다. 테스트용 서재의 `/app/data/books/OutlineFinal`에서 PDF 네 개를 확인했다. 15203에서는 운영 중인 이미지에 목차 데이터만 등록했다.

| Chrome에서 지연시킨 요청 | 클릭 후 관찰 결과 |
| --- | --- |
| 저장 목차 GET | 5,567ms에 PDF 내장 목차 표시 |
| 최초 목차 PUT | 5,736ms에 내장 목차 표시. 저장 목차 GET은 404 |
| 임시 PDF.js 책 읽기 | 30,487ms에 오류와 **다시 시도** 표시. 요청 종료 사유 `net::ERR_ABORTED`. 재시도에서 최초 저장 PUT 200, 새 브라우저에서 저장본 조회 성공 |
| 내장 목차가 없는 PDF에서 저장 목차 GET | 5,580ms에 **다시 시도** 표시. 저장소 응답을 복구한 뒤 기존 항목 조회 성공 |

`viewer-outline-open`으로 `목차` 대화상자를 열었다. `pdf-outline-list`, 목록 내 `pdf-outline-entry`, `다시 시도` 버튼과 `페이지 번호` 입력란으로 검증했다. 네 시나리오 모두 미처리 페이지 오류 0건이었다. 테스트 PDF를 띄운 뒤 목차 전용 PDF 요청을 지연시켰다. [시나리오 및 트레이스](../../../../../test/20261128/outline-loading-regression/) · [브라우저 결과](../../../../../test/20261128/outline-loading-regression/browser.json) · [홈 스모크](../../../../../test/20261128/outline-loading-smoke/report.md).

`node --test packages/pdfit/tests/pdf-outline.test.mjs packages/pdfit/tests/pdf-outline-storage.test.mjs`에서 22개 통과, 1개 건너뜀. PostgreSQL 직접 접속이 필요한 테스트는 건너뛰었고, 브라우저 시나리오에서 컨테이너 DB 저장과 재조회를 확인했다. 실행 범위는 Free의 PDFGPU 뷰어다.
