# Books table and tag query optimization

## Change

Added a normalized `books` table containing folder, filename, size, and
modified time. The refresh indexer upserts the current filesystem snapshot into
that table. Tag results now return each book's complete tag array in one SQL
query, so the Tag page no longer performs one request per book.

## Evidence

| Check | Before | After |
| --- | ---: | ---: |
| `books` rows | not present | 713 |
| `book_tags` rows | 1,234 | 1,234 |
| `컴퓨터과학` API response | 27ms list plus 238 book requests | 65ms single response |
| Browser tag page load | 30,645ms | 530ms |
| `/api/tags/book/*` requests | 238 | 0 |

The PostgreSQL plan already used `tags.name`, `book_tags(tag_id)`, and the
composite book index; the delay was caused by the frontend N+1 request pattern,
not a missing index.
