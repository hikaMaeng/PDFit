# 사이드바 태그 이름 표시 폭 검증

2026-11-23 16:17 KST, Windows의 Free Docker 서비스 `http://127.0.0.1:15203`에서 Chromium 데스크톱(1440×1080)과 터치 에뮬레이션(390×844)으로 측정했다. [검증 계획](../../plans/tag-sidebar-spacing-20261123.md)

## 배포

- `npm run deploy:standalone` 성공. TypeScript·Vite를 포함한 빌드는 31.063초에 완료했다.
- `pdfit-pdfit-1`은 `healthy`이고 `127.0.0.1:15203`의 `/health`는 HTTP 200이었다. LAN 주소 `192.168.0.6:15203`에서도 `/health`의 `ok: true`를 확인했다.
- 컨테이너에서 `BOOKS_ROOT`를 읽을 수 있었고 배포 후 PDF 729개를 폴더 2개에서 색인했다.

- 각 이름의 텍스트 폭은 약 90px이었다. 세 개 모두 배포 전에는 말줄임으로 표시됐고 배포 후에는 한 줄에 온전히 표시됐다. 데스크톱과 터치, 배포 후 라이트와 다크 모드에서 같은 결과를 확인했다.
- `설계 및 테스트` 버튼으로 부모 폴더를 찾고 `lnb-folder-tag-row`에서 정확한 이름으로 하위 행을 구분했다. `lnb-folder-tag-remove`를 첫 도구 버튼으로 사용했다. 태그 행의 버튼 3개와 겹침 없는 간격을 확인했고 브라우저 페이지 오류는 0건이었다.
- `node apps/pdfit/tests/tag-folders-browser.mjs` 통과. 드래그 앤 드롭, 접힘 상태 복원, 이름을 눌러 태그 페이지로 이동, 폴더에서 빼기, 데스크톱 키보드 및 터치로 이동 메뉴 사용을 확인했다. 임시 폴더 정리 후 기존 폴더 8개와 태그 115개를 확인했다.
- `node apps/pdfit/tests/tag-editing-browser.mjs`는 여러 탭을 연 상태에서 중복 이름 저장 응답을 30초 안에 받지 못했다. 진단 실행에서 브라우저가 저장 양식을 제출하고 PATCH를 요청한 것을 확인했다. 브라우저의 `/api/events` 연결만 차단한 재실행에서는 실제 서버의 중복 409, 편집 저장, 두 탭·뷰어·인덱스 갱신, 터치 편집 및 임시 데이터 정리가 모두 통과했다. 배포된 서비스의 이벤트 경로에는 변경을 가하지 않았다.
- 작업 트리의 `test/20261123/tag-sidebar-spacing/`에 측정 스크립트 및 JSON, 데스크톱·터치 화면 캡처를 남겼다. 같은 라이브러리에서 `node test/20261123/tag-sidebar-spacing/measure.mjs after`로 측정한다. 다크 모드는 `after-dark` 인자를 사용한다.
