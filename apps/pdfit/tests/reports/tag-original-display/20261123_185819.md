# 태그 원문 표시 검증 결과

2026-11-23 18:58 KST · Free Docker · `http://127.0.0.1:15203` · 헤드리스 Chrome

- 수정 전 브라우저에서 `AI App`을 포함한 번역 요청 1건을 잡았다. `AI 앱` 응답을 돌려주자 태그 상세 제목과 사이드바가 모두 `AI 앱`으로 바뀌었다. 태그 API 값은 `AI App`이었다.
- `npm run deploy:standalone`이 공용 패키지와 앱 빌드 2건을 완료하고 Free 컨테이너를 갱신했다. Docker는 `healthy`, 외부 포트의 `GET /health`는 `{"ok":true,"service":"pdfit"}`를 반환했다. 컨테이너 안에서 `pdfit-usbshare1` 마운트와 `BOOKS_ROOT`의 항목 728개를 읽었고 앱 인덱스는 두 폴더에서 PDF 731개를 보고했다.
- [검증 계획](../../plans/tag-original-display-20261123.md)의 브라우저 검사 27건이 통과했다. 인덱스 제목 115개가 API 값과 일치했다. 번역 요청 8건의 입력은 모두 일반 서재 폴더 이름이었고 `AI App`은 0건이었다. 브라우저 예외와 태그 쓰기 시도는 0건이었고 책별 태그 관계는 실행 전후 동일했다.
- 사이드바는 행 안의 정확한 텍스트, 칩은 `title`과 보이는 텍스트, 인덱스는 카드 안의 제목으로 검증했다. 폴더 메뉴와 수정 툴팁의 역할은 바깥 컨테이너에 있으므로 번역 방지 속성은 안쪽 텍스트 요소에서 확인했다. 검색·관리창·뷰어 검증은 실제 서재의 책으로 진행했고, 즐겨찾기 응답만 해당 책으로 대체했다.
- 저장소 헤드리스 스모크를 통과했다. 시나리오 증거는 `test/20261123/tag-original-display/result.json`과 `sidebar-cover.png`에, 스모크 증거는 `test/20261123/185118_headless-browser-test/`에 있다.
- i18n 검사는 수정 전후 동일하게 AI 서버 설정 화면의 정적 리소스 규칙 위반 8건을 보고했다. 이 화면은 이번 변경 범위 밖이다. Pro 런타임과 브라우저의 실제 자동 번역 엔진은 실행하지 않았다. 번역 API 응답은 테스트에서 제어했고 브라우저 번역 방지는 DOM 속성으로 확인했다.
