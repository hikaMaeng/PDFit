배포 전 빌드에서 끝에 `/`가 붙은 태그 URL, 응답 지연 동안의 화면 이동, 미분류 개수, 폴더 목록 재시도, 삭제 오류 알림이 모두 기존 동작에서 실패했다. 중간 수정에서도 태그 인덱스의 첫 렌더가 지연되면 홈으로 이동했다. 브라우저의 현재 경로를 읽도록 바꾼 후 미리보기와 배포 주소에서 모두 통과했다.

배포 후에는 일반 태그와 폴더 안 태그를 각각 삭제해 홈의 라이브러리·인덱스 링크가 동작하고 미분류 배지와 목록이 1건을 표시하는지 확인했다. 삭제 응답을 보류하고 움직인 경우 최종 경로는 `/tag-index`였다. 폴더 목록 503은 홈의 **다시 시도**로 복구됐고, 삭제 500은 오류 알림과 기존 태그 행을 표시했다. API를 가로채 테스트했으며 실제 태그 삭제와 Pro는 실행하지 않았다.

`PDFIT_TEST_CHANNEL=chrome`, `PDFIT_TEST_ORIGIN=http://127.0.0.1:15203`, `PDFIT_TEST_ARTIFACT_DIR=test/20261124/tag-delete-active`로 `node apps/pdfit/tests/tag-delete-active-browser.mjs`를 실행했다. 태그 행과 미분류 배지는 기존 테스트 ID, 홈 링크와 삭제·재시도 버튼은 역할과 이름으로 확인했다. 증거는 같은 디렉터리의 `report.json`, `deploy.log`, `delayed-delete-kept-route.png`, `folders-retry-retry.png`, `mobile-grouped-untagged.png`에 있다.
