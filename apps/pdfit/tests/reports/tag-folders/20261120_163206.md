# 태그 폴더 드롭 영역과 선택 메뉴 검증

- 실행 시각: 2026-11-20 16:27~16:32 KST
- 환경: Windows, PDFit Free Docker Compose, `http://127.0.0.1:15203`, Playwright와 headless Chrome
- 계획: [태그 폴더](../../plans/tag-folders-20261120.md)

| 검증 | 결과 |
|---|---|
| 독립 실행형 빌드·배포 | `npm run deploy:standalone` 통과. 기존 NAS 볼륨의 PDF 720개와 책 폴더 2개 색인. Docker `healthy`, `/health` HTTP 200 |
| 브라우저 스모크 | HTTP 200, `main` 표시, 콘솔 오류와 `pageerror` 0 |
| 폴더 드롭 | 빈 본문, 기존 태그 위, 접힌 제목에서 각각 `PUT` 200 및 서버 소속 반영. 폴더 안 태그를 다른 폴더로 드래그한 뒤 양쪽에 표시 |
| 일반 태그 작업 | 휴지통 클릭 후 삭제 확인 취소. 목록 하단에서 Enter로 폴더 메뉴 열기, Escape 후 버튼으로 포커스 복귀, Enter로 폴더 선택 및 서버 저장. URL 유지 및 일반 목록에서 태그 제거 |
| 모바일 에뮬레이션 | 390×844 터치 환경에서 사이드바 열기, 폴더 버튼과 항목 탭, 서버 소속 저장 및 일반 목록에서 태그 제거 |
| 폴더가 없는 상태 | 브라우저에서 `GET /api/tag-folders`만 빈 배열로 대체. 메뉴에 선택 불가 안내 표시 |
| 데이터와 오류 | 임시 폴더 2개 정리 후 기존 폴더 5개와 소속이 실행 전과 일치. 태그 목록 139개 유지, 시나리오 `pageerror` 0, 해당 실행 구간의 Docker 로그에 `error`·`fatal` 검색 결과 없음 |
| 라우트 테스트 | `node --test packages/pdfit/tests/tag-folders.test.mjs` 2개 통과, 별도 DB URL을 쓰는 격리 스키마 테스트 1개 건너뜀. 브라우저의 쓰기 요청은 독립 실행형 PostgreSQL에 저장됨 |
| 저장소와 번역 | `npm run verify:repo` 통과. 새 메시지 3개 각각 번역 8개 확인. 범용 번역 검사에는 작업 전부터 `AIServersTab.tsx`의 위반 8개가 보고됨 |

재현 환경에서 `PDFIT_TEST_CHANNEL=chrome`과 `PDFIT_TEST_ARTIFACT_DIR`을 설정하고 `node apps/pdfit/tests/tag-folders-browser.mjs`를 실행한다. 폴더와 태그 행은 안정된 테스트 ID로 범위를 좁히고 폴더 작업은 버튼 이름, `menu`, 폴더 이름의 `menuitem`으로 확인했다.

초기 드래그에서는 시작 행과 대상이 화면에 동시에 들어오지 않아 Playwright가 다른 태그에서 드래그를 시작했다. 브라우저 콘텍스트에서 기존 폴더를 접고 데스크톱 뷰포트를 1440×1440으로 넓혀 시작 행과 대상이 함께 보이는 상태에서 재현했다. 실제 터치 기기의 드래그는 검증 범위에 포함하지 않았다.

스크린샷은 `test/20261120/tag-folder-actions-verified/`에 저장했다. `two-folders.png`는 같은 태그의 두 폴더 표시, `folder-menu.png`와 `folder-menu-mobile.png`는 데스크톱과 모바일의 폴더 선택 메뉴를 보여 준다.
