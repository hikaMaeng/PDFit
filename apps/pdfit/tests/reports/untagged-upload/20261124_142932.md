# Library changes during a scan

2026-11-24 14:29 KST. Windows, PDFit Free Docker, mounted CIFS library, PostgreSQL and headless Chrome. The build includes the tag-folder release at `54bea51`. [Test plan](../../plans/untagged-upload-20261124.md)

| Check | Result |
| --- | --- |
| Controlled HTTP races | Six cases passed. The second upload committed while the old scan read was paused and the cancelled scan skipped remaining reads. PDF and folder deletion survived scan restart. A same-name upload waited for deletion. A delete waited for an already-started scan write. A watcher permission error kept the PDF row. These cases used real temporary files and a controlled metadata store. |
| Server checks | 16 passed and one skipped. The separate PostgreSQL test requires `PDFIT_TEST_DATABASE_URL`. |
| Docker deploy | `npm run deploy:standalone` succeeded in 143.32 s. PostgreSQL performed crash recovery during startup and became ready. The container was healthy with zero restarts. Loopback and LAN port 15203 returned HTTP 200 and the CIFS library was readable. Startup refresh found 733 PDFs across two folders. |
| Live parallel requests | On `http://127.0.0.1:15203`, sent refresh with a same-name upload, PDF delete, and folder delete against a uniquely named fixture. All responses were HTTP 200. Untagged returned the new size after reupload and no fixture row after either deletion. The controlled tests established the internal ordering. |
| Browser | The real upload became visible at `pdf-filename-line` and incremented `lnb-untagged-count` while the tag summary was held. No page errors. The sole console error was the expected Free resumable upload probe returning 404. |

A scan stops at a filesystem read boundary. If PostgreSQL has started applying the snapshot, the mutation waits for that write and the replacement scan runs after pending mutations. The controlled watcher test covers delivered events. The live checks cover changes issued through the API.
