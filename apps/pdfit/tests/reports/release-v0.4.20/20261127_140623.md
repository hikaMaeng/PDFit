# PDFit Free 0.4.20 deployment verification

2026-11-27 14:06 KST. GitHub `main` returned release commit `4eff1d5` before production deployment.

| Check | Result |
| --- | --- |
| Build and manifests | The repository check, release contract, and Free build passed. The release used PDFGPU `0.1.12-pdfit.1`. |
| Page change handling | The open comments window receives the active-page change through the viewer callback. Both engines made zero extra list requests when the window was closed or set to Latest. Current page fetched the first matching comments page and canceled a superseded request. |
| Incremental rendering | A comment visible for two consecutive PDF pages retained the same article DOM node across an update. Markdown rendering is memoized by body. |
| Isolated Chromium | The full viewer comments scenario passed with both engines, including saved references, the empty message, attachments, and popup controls. |
| Database backup | `pg_dump` produced a 422,293-byte archive. `pg_restore --list` returned 137 lines, and the container and host SHA-256 hashes matched. |
| Production environment | Docker reported Free healthy with zero restarts. Both the Free image and its shared runtime reported `0.4.20`. The loopback and LAN health endpoints on port 15203 returned HTTP 200. PostgreSQL reported an array column for reference pages. The mounted library and index both contained 744 PDFs. |
| Production Chromium | Eight read-only popup scenarios passed across PDF.js and PDFGPU. Both engines returned HTTP 200 when switching a real book to Current page. Chromium recorded zero page exceptions. The five console errors matched the deliberately blocked writes. |

`node apps/pdfit/tests/viewer-comments-browser.mjs`. It used the locator contract
in the [viewer comments test plan](../../plans/viewer-comments-20261125.md).

checkout. The deployment log, screenshot and trace files are under
