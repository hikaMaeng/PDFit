## 기각·정정

- 처음에 "도메인이 Pro 서비스"라고 가정했으나 틀렸다. 도메인은 Free(`host.docker.internal:15203`)이고 프록시 설정은 이 작업에서 건드리지 않았다.
- "서버나 프록시 문제"라는 가설은 서버 API 직접 응답, 프록시 로그, 로컬 페이지 정상 동작으로 기각했다.
- 요청 코드(`fetch('/api' + url)`)는 0.4.5와 동일하므로 0.4.6 변경이 원인이 아니다.

## 한계

- 운영 도메인(`https://pdfit.neurondev.net`)에서의 실제 확인은 하지 않았다. 도메인 쪽 브라우저 상태는 볼 수 없고 계정을 사용하지 않았다. 같은 구조(기본 인증 프록시 + 계정이 든 주소)를 로컬에서 재현해 검증했다.
- 계정 주소에서 이후 요청이 인증되는 것은 이 Chrome 157의 HTTP 인증 캐시 동작에 의존한다(테스트에서 인증된 요청 7건, 미인증 0건으로 확인). 다른 브라우저는 확인하지 않았다.
- 이 수정은 `fetch` 해석만 고친다. 주소에 계정을 넣으면 방문 기록·북마크에 평문으로 남는 문제는 그대로다.
