# 기울임 보정 토글과 WebGPU 전용 뷰어

2026-11-27 16:35 KST. 격리 Free Docker의 `http://127.0.0.1:15233`에 0.4.24를 빌드했다. 앱과 공유 런타임의 버전을 확인했다. Docker는 `healthy`, `GET /health`는 HTTP 200이었다. 컨테이너에서 목차 테스트 PDF 다섯 개를 확인했다.

## 브라우저 결과

Chrome 158.0.8127.89는 별도 WebGPU 플래그 없이 NVIDIA Lovelace 어댑터를 사용했다.

| 검사 | 관찰 결과 |
| --- | --- |
| 기본값 | 새로 연 문서에서 버튼의 `aria-pressed` 값은 `false`. 기울기 검출을 요청한 워커 메시지는 0건 |
| 켜기와 끄기 | 테스트 스캔은 +1.172°와 −1.172°였다. 켜면 두 페이지가 각각 +0.001°와 −0.001°로 바뀌었다. 2페이지에서 끄면 −1.172°로 돌아왔다 |
| 문서 유지 | 토글을 누르는 동안 현재 페이지와 캔버스가 유지됐다. PDF를 다시 요청한 횟수는 0건 |
| 첨부 화면 | 첨부 PNG에서 종이 영역을 잘라 한 페이지 PDF로 만든 뒤 분홍색 영역의 윗변을 측정했다. +0.815°에서 −0.224°로 줄었다 |
| 확대, 주석, 클립 | 확대 뒤에도 반듯한 선을 확인했다. 주석과 클립은 원본 PDF 좌표에 맞았고 클립을 드래그할 때 스크롤 변화는 0px이었다 |
| WebGPU 실패 | GPU API가 없는 경우와 어댑터를 받지 못한 경우 모두 오류가 표시됐다. `engine=legacy`가 들어간 주소에서도 대체 뷰어가 뜨지 않았고 PDF 요청은 0건이었다 |
| 목차 회귀 | 단면, 양면, 연속 스크롤, 모바일에서 항목 이동과 페이지 저장을 확인했다. 저장 오류 이후 재시도와 새 컨텍스트 재조회도 통과했다 |

운영 주소의 Chrome 기능 검사에서 루프백 `127.0.0.1:15203`은 보안 컨텍스트였고 WebGPU 장치를 만들었다. LAN의 `http://192.168.0.6:15203`은 HTTP 200을 반환했지만 WebGPU API를 노출하지 않았다. [Chrome WebGPU 접속 조건](https://developer.chrome.com/docs/web-platform/webgpu/troubleshooting-tips)

## 재현과 범위

`PDFIT_TEST_ORIGIN=http://127.0.0.1:15233`으로 `node apps/pdfit/tests/viewer-deskew-browser.mjs`와 `node apps/pdfit/tests/viewer-outline-save-page-browser.mjs`를 실행했다. `기울임 보정` 버튼을 역할과 이름으로 찾았고, `viewer status`의 백엔드와 캔버스에서 읽은 각도를 대조했다. 스모크와 두 브라우저 시나리오에서 미처리 페이지 오류는 0건이다. 결과와 스크린샷은 `test/20261127/viewer-deskew-toggle-headless-browser-test/`에 있다. [기울임 보정 테스트 계획](../../plans/viewer-deskew-20261127.md)

PDFGPU 코어 79개, PDFit 관련 Node 테스트 34개, 저장소 검사와 릴리스 계약 검사가 통과했다. 별도 URL을 요구하는 PostgreSQL 단위 테스트 1개는 건너뛰었고, 격리 목차 시나리오에서 실제 DB 저장과 재조회를 확인했다. 전체 인수 테스트와 Pro 런타임 검증은 이번 실행에서 다루지 않았다. 운영 Free 런타임은 0.4.23이다.
