## Results

The deskew scenario used the deployed viewer bundle at `/viewer/deskew/pages.pdf?driveFileId=deskew`. Playwright intercepted the three-page scan PDF and its metadata API writes. Pixel angles below are signed degrees.

In both GPU viewer backends, the drawn annotation stayed within two CSS pixels of the pointer endpoints and posted a line with +1.154° slope in source PDF coordinates. Its source midpoint was 232.57 PDF points down the page for a guide at 232.50 points. The clip retained the blue guide, used a source rectangle containing the original line coordinates, and displayed a bookmark overlay rotated by -1.187°. The clip drag left `scrollTop` unchanged. The deskew scenarios recorded zero uncaught page errors.

The installed 0.4.20 control showed +1.172° in WebGPU on page 1 and failed the deskew assertion as expected. The first 0.4.21 integration run exposed a 24 CSS pixel offset between the page raster and overlay origin. The next run exposed a 46 CSS pixel scroll during a clip drag when the renderer received mouse focus. Moving the padding outside the shared surface and preventing the native pointer-down action resolved the two offsets.
