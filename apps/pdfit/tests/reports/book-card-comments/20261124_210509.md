# Book card and comments test report

## Environment

2026-11-24 21:05 KST. Windows Docker Desktop, isolated Compose project
`pdfit-book-card-preview`, Free on `http://127.0.0.1:15347`.
The app indexed two fixture PDFs across three folders. Its health check
returned `{"ok":true,"service":"pdfit"}`, and Docker reported healthy.
The Compose project mounted fixture books, metadata and clip storage separately.

## Results

- `npm run deploy:standalone` built and deployed the Free artifact.
- The Chromium scenario passed with a 1280 × 850 desktop view and a 390 × 844
  touch view. It observed the auto-tag control after the tags, the leftmost
  Comments button, and three items in the file actions menu.
- Comment create and edit returned `201` and `200`. A blank post returned
  `400` and an edit from another book returned `404`. The board displayed
  one body per page and preserved the edited post through browser reload.
- Rename returned `409` for a collision and `200` for a new name. The PDF
  retained its SHA-256, tag, favorite, viewer page, clip ID, clip memo, and
  comment posts. Folder move preserved the file and remaining comment.
  Deleting the fixture PDF removed its comments.
- A separate Chromium check renamed a fixture from a tagged cover and restored
  its name from a search-result cover. Both lists updated and both posts remained.
- `cover-card-overlay-deployed-browser.mjs` passed on desktop, tablet and
  phone. It verified four equally sized footer controls and the hover/touch
  information overlay geometry.
- The volume guard regression suite passed five checks. The independent
  clip-count SQL test skipped without a test database URL. The browser scenario
  exercised clip-count preservation against the preview's PostgreSQL.

## Evidence and scope

Scenario and trace are reproducible with the
[test plan](../../plans/book-card-comments-20261124.md). The local evidence is
under `test/20261124/210500_book-card-comments/`, including the four PNGs,
`trace.zip`, and the overlay test's `result.json`.

The scenario used scoped button and menu item names, modal text, and the
`pdf-cover-*` regions. It reported zero unhandled desktop page exceptions.
It exercised AI button placement and touch access. It did not call an AI
provider or use the production NAS mount. Older hosted-browser scripts had
their card locators updated and passed syntax checks.
