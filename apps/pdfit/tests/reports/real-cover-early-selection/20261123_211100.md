# 표지 검색 중 후보 선택 검증 결과

## 실행 환경

- 2026-11-23 21:08–21:11 KST. Free UI `http://127.0.0.1:15203`, Chrome 헤드리스.
- 브라우저 시나리오 `http://127.0.0.1:55800/tag/Cover-fixture`는 배포된 UI를 불러왔다. 표지 API는 같은 작업 트리에서 빌드한 `createCoversRouter`를 실행했고, 임시 저장소와 YES24 및 Open Library 응답 픽스처를 사용했다.

## 실행과 관찰

| 항목 | 결과 |
| --- | --- |
| `npm run deploy:standalone` | 빌드와 컨테이너 재생성 성공. Turbo 빌드 45.804초. 서비스가 건강 상태를 보고했고 `/health`는 `{"ok":true,"service":"pdfit"}`를 응답했다. 컨테이너에서 PDF 732개를 확인했다. |
| `node --test packages/pdfit/tests/real-covers.test.mjs` | 10/10 통과. 출처별 검색, 표지 저장, 원본 복원, 미리보기 재사용 포함. |
| `run-headless-browser-test.mjs --url http://127.0.0.1:15203` | 스모크 통과. 문서 200, 콘솔 오류 0, 페이지 오류 0. |
| 검색 도중 첫 후보 선택 | 검색 스피너가 보일 때 후보 이미지가 로드되고 버튼이 활성화됐다. 브라우저 요청은 `ERR_ABORTED`, 서버가 진행하던 외부 호출은 클릭 시작 60ms 후 `AbortError`로 취소됐다. 적용 중 후보 버튼과 검색 버튼이 잠겼다. |
| 적용 실패 후 재시도 | 의도한 첫 PUT 404가 표시됐다. 취소한 Open Library의 경고 없이 후보가 남았다. 다시 선택하자 검색 없이 PUT 200으로 적용됐다. |
| 새 검색 도중 바로 적용 | 아직 검색 중인 후보를 선택하자 요청 취소와 PUT 200이 확인됐다. 대화상자가 닫히고 썸네일 URL에 새 버전 `mwt85wto`가 붙었다. 저장소의 표지 URL이 선택한 이미지와 일치했다. |
| 닫기와 다시 열기 | 닫을 때도 브라우저와 서버가 요청을 취소했다. 다시 열어 반환한 503은 출처 경고로 표시됐다. YES24 후보는 선택 가능했고 페이지 오류는 0건이었다. |

## 재현 및 증거

- [테스트 계획](../../plans/real-cover-early-selection-20261123.md)의 명령과 환경변수로 재현한다. `dialog`, 후보 버튼의 접근 가능한 이름, `alert`를 사용했다. 카드 열기와 썸네일에는 `pdf-cover-real-cover`, `pdf-cover-thumbnail`을 사용했다.
- 화면은 `test/20261123/210835_headless-browser-test/early-selection/`의 `partial-results.png`, `applying-after-cancel.png`, `cover-applied.png`에 저장했다. 스모크 보고서는 `test/20261123/210848_headless-browser-test/report.md`에 있다.
- 브라우저 시나리오에서 외부 서비스의 실제 지연이나 가용성을 측정하지 않았다. 표지 쓰기는 임시 저장소에서 실행했다. Pro는 배포하지 않았다.
