## 기각된 가설과 수정

- "인덱스 숫자와 사이드바 숫자가 어긋날 수 있다"(`book_tags`에 `books` 행이 없는 고아 연결): 실제 라이브러리에서 태그 127개 전부 일치해 기각했다. 이 일치는 브라우저 테스트가 태그마다 단언한다.
- 머리글 칩을 처음에 "책 N권"으로 만들었으나 1319는 책 수가 아니라 태그-책 연결 수다(한 책이 여러 태그에 걸리면 여러 번 센다). "책 연결 N건"으로 바꾸고 사이드바 `tag-assignment-total`과 같은 값임을 테스트로 고정했다.
- 브라우저 테스트의 첫 버전은 대비 결과에 항상 `null`인 `mode` 필드를 남겼다. 증거를 오해하게 만들어 제거하고 모드 이름을 직접 기록하도록 고친 뒤 다시 실행했다. 위 수치는 그 최종 실행의 `result.json`에서 옮겼다.

## 한계

- 요청의 4번 항목은 내용이 비어 있어 구현하지 않았다.
- "썸네일 보기와 닮은 스타일"은 기계 판정이 아니라 스크린샷을 눈으로 본 판단이다. 카드에는 표지 이미지가 없다(요청의 "각 카드의 구성이 다르다"를 그렇게 해석했다).
- 핀터레스트식 배치는 CSS 다단이다. 카드는 한 단을 위에서 아래로 채운 뒤 다음 단으로 넘어가므로 읽는 순서가 "왼쪽→오른쪽"이 아니다. 가장 큰 카드는 `프로그래밍`(223권, 5463px)이라 페이지가 길다.
- 하이드레이트된 브라우저 캐시 경로(`listCachedTagIndex`, Pro 런타임이 사용)는 타입 검사만 통과했고 실행 검증하지 않았다. Pro는 배포하지 않았다.
- 브라우저 D(빈 상태·오류)는 서버 응답을 가로챈 시나리오다. 390px 검증은 Playwright 모바일 에뮬레이션이지 실제 기기가 아니다.
- 배포 이미지는 작업 트리에서 빌드했고, 작업 시작 시 작업 트리는 깨끗했다.
