# Viewer outline management test report

## Timestamp and environment

2026-11-20 16:31:59 KST. Free standalone Docker project `pdfit-outline-check` on `http://127.0.0.1:15233`, with PostgreSQL 17 and two synthetic PDFs under `/app/data/books/OutlineFixture`. Ran Chromium with a Korean locale at 1440×900 and 390×844. The PDFGPU scenario used Chromium’s SwiftShader backend.

## Executed checks

- `npm run deploy:standalone` built both workspace packages and started the isolated container. Library refresh found two fixture PDFs. Docker reported `healthy` and `/health` returned HTTP 200 with `{"ok":true,"service":"pdfit"}`.
- PDF extraction tests passed 4/4 on the host. Storage and API tests passed 10/10 in the isolated Docker container with `PDFIT_TEST_DATABASE_URL` pointing to its real PostgreSQL socket.
- Chromium scenarios passed 6/6. Covered editing and page validation, retry after an injected PUT 503, navigation after reload, confirmed and canceled deletion, and manual creation for a PDF without an embedded outline. Both engines regenerated the original outline. The deletion request returned 204 and a subsequent automatic initialization returned 412. The final run reported zero page errors.
- Both fixture PDFs had identical SHA-256 hashes before and after testing. All 12 new resource keys have values in each of the eight primary locales.

## Failures and coverage limits

An initial browser run caught a footer button being reused as the form submit button within the same click. The footer controls now remount when the dialog changes mode. The final browser run exercised opening the editor and saving as separate actions. The repository-wide i18n checker reports eight pre-existing matches in `AIServersTab.tsx`. Hosted Pro storage and the live library were outside this run.
