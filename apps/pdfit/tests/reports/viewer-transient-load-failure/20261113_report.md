# 뷰어 흰 페이지 미복구·passive 휠 오류 보고서 — 2026-11-13

- 계획: `apps/pdfit/tests/plans/viewer-transient-load-failure-20261113.md` (사용자 보고 원문 포함)
- 환경
  - Windows 11, Docker Compose `pdfit`(Free, `127.0.0.1:15203`)
  - Playwright + 설치된 Chrome
  - 책: `이북/밑바닥부터 시작하는 딥러닝.pdf` (103,502,316 B, 구간 로딩), 목표 79쪽
- 증거: 이 폴더의 `20261113_before-fix/`, `20261113_after-fix-single/`, `20261113_after-fix-double/`, `20261113_regression/`

## 원인

- **흰 페이지**
  - PDF.js 뷰어는 큰 파일을 구간으로 받는다. 페이지를 그리는 순간 필요한 구간 요청이 실패하면 `page.render()`가 실패하는데, 이 오류를 버리고 있었다(`PdfPage.tsx` `.catch(() => {})`).
  - 다시 그리게 해도 소용없었다. 처음에 넣은 페이지 단위 재시도(1·2·4·8초)로는 복구되지 않았다. 디버그 실행에서 502를 푼 뒤 PDF 요청이 0건이었고(`REQS []`), 상태는 계속 `error`였다. PDF.js가 실패한 구간을 "요청됨"으로 둔 채 다시 요청하지 않는 것으로 보인다.
  - 그래서 같은 문서 객체로는 복구할 수 없다.
- **502 출처:** 이 컴퓨터의 Free 컨테이너는 그날 같은 저장소의 여러 세션이 거듭 다시 배포했다. 시작 시각 01:53, 01:56, 01:59, 02:03, 02:05, 02:07 등이다. 재시작 사이에는 502가 날 수 있다. 사용자 화면의 502가 이 재시작 때문인지는 확인하지 못했다(그 시각 프록시 로그는 보지 않음).
- **passive 경고:** 두 뷰어의 휠 처리(페이지 모드 넘김, 손 도구 팬, GPU 휠 전달)가 React `onWheel` 안에서 `preventDefault`를 불렀다. React의 휠 리스너는 passive라서 무시되고 경고가 남는다.

## 수정

- **흰 페이지:** `PdfViewer`의 `recoverDocument`가 처리한다.
  - 페이지 렌더 실패나 페이지 로드 실패가 나면 동작한다.
  - 1바이트 구간 요청으로 서버 응답을 먼저 확인한다.
  - 응답하면 같은 주소로 문서를 새로 열어 바꿔 끼우고, 현재 페이지부터 다시 불러온다.
  - 실패하면 1·2·4·8초 간격으로 다시 시도한다.
  - 페이지·배율·보기 방식은 유지한다. 교체된 옛 문서의 페이지에서 나는 오류는 무시한다.
- **passive 경고:** `useNonPassiveWheel`로 `{ passive: false }` 네이티브 리스너를 단다. 적용 대상은 PDF.js 뷰어 표면과 GPU 뷰어 표면이다.

## 한계

- **사용자 환경과 같은 조건으로 확인하지 않았다.** 사용자가 쓴 `pdfit.neurondev.net` 프록시 뒤 환경에서는 확인하지 않았다. 502를 Playwright로 주입해 재현했다.
- **GPU 뷰어(`?engine=gpu`)는 이 결함의 대상이 아니다.** 문서 전체를 메모리로 받기 때문이다. 같은 실패 주입은 하지 않았다.
- **같은 PDF.js 문서 객체로는 실패 구간이 다시 요청되지 않는다는 점은 관찰로만 확인했다.** PDF.js 소스에서 그 이유를 짚지는 않았다.
