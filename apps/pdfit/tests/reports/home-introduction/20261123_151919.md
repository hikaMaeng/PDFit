## 빌드와 Docker

- `npm run deploy:standalone` 최종 실행은 62.90초에 종료 코드 0을 반환했다.
- `pdfit-pdfit-1`은 `healthy`였다. `127.0.0.1:15203`과
  `192.168.0.6:15203`의 `/health`가 모두 HTTP 200을 반환했다.
- 컨테이너의 라이브러리에서 PDF 719개, 폴더 API에서 폴더 2개와 PDF 719개를 확인했다.
- `npm run verify:release-contract`가 통과했다. 문서 구조 검사에서 위반은 0건이었다.
  번역 검사기는 기존 Settings 화면에서 동일한 8건을 보고했다. 홈 문구 30개에는
  각각 12개 언어 값이 있다.

## 브라우저 시나리오

`PDFIT_TEST_ORIGIN=http://127.0.0.1:15203`과 `PDFIT_EVIDENCE_DIR`을 지정하고
`node apps/pdfit/tests/home-introduction-browser.mjs`를 실행했다. 별도 데이터 디렉터리와
PDF 1개로 격리 Docker를 먼저 검증한 뒤, 기존 Free 주소에서 최종 빌드를 재검증했다.

| 화면 | 관찰 결과 |
| --- | --- |
| 한국어 1440px 다크 | 서재와 AI가 두 열로 표시됐다. 기본 폴더, 태그 인덱스, 미분류, 즐겨찾기, 클립, AI 설정 링크 6개가 각각 해당 화면을 열었다. |
| 한국어 375px 라이트 | 두 기능 섹션이 세로로 배치됐다. 라이브러리 버튼이 활성화되고 가로 넘침이 없었다. |
| 아랍어 1280px 다크 | 초기 배포에서 왼쪽 사이드바가 본문을 덮는 문제를 재현했다. 수정 후 사이드바가 오른쪽에 배치됐고 AI 설정 링크가 클릭 가능한 상태였다. |
| 영어 1024px 라이트 | 영어 제목과 왼쪽에서 오른쪽으로 읽는 방향을 확인했다. 가로 넘침이 없었다. |

최종 실행에서 페이지 오류는 0건이었다. 홈은 `main`, 제목, 이름이 있는 영역과 링크로
찾았다. 미분류·즐겨찾기 도착 화면에는 기존 테스트 ID를 사용했다. 이름 번역 API는
요청한 이름을 그대로 응답하는 테스트 대역을 사용했다. 검증 범위는 Free 홈의 표시와
탐색이다.
