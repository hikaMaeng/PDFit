# 목차 팝업 유지와 현재 페이지 지정

2026-11-27 15:07 KST. [테스트 계획](../../plans/viewer-outline-save-page-20261127.md).

## 환경

`npm run deploy:standalone`으로 별도 Free Compose 프로젝트 `pdfit-outline-current-page`를 빌드했다. 루프백 포트 `15233`과 테스트 전용 네트워크, 서재, PostgreSQL 데이터, 북마크 경로를 사용했다. 첫 배포에서 Docker 기본 주소 풀이 소진돼 테스트 네트워크에 미사용 서브넷을 지정한 뒤 재실행했다. 두 워크스페이스 빌드, 라이브러리 새로고침, `GET /health` 200 및 Docker `healthy`를 확인했다. 컨테이너의 `/app/data/books/OutlineFixture`에서 테스트 PDF 다섯 개를 확인했다.

## 결과

| 브라우저 시나리오 | 관찰 결과 |
| --- | --- |
| PDF.js 단면과 PDFGPU 모바일 | Chapter 2를 눌러 3페이지로 이동한 뒤 열린 목차에서 Chapter 1을 1 → 3으로 저장했다. 뷰어는 3페이지를 유지했고 화면과 DB가 같은 번호를 표시했다. |
| 저장 실패와 재시도 | 목차 PUT 한 건에 HTTP 503을 반환했다. 팝업 안에 오류가 표시됐고 이전 목적지와 현재 페이지가 유지됐다. 재시도는 200이었다. |
| 미지정 항목과 재열기 | Missing을 현재 페이지에 연결했다. 새 브라우저 컨텍스트에서 수정한 세 항목의 번호를 확인했다. |
| 양면과 연속 스크롤 | 양면 모드에서 화면에 표시된 첫 페이지를 저장했다. 연속 스크롤 모드에서는 현재 페이지를 지정할 때 뷰어 스크롤 위치가 유지됐다. |
| 팝업 회귀 | 이동, 리사이즈, 문서별 크기 복원, X, Esc와 포커스 반환, 아랍어 닫기 버튼을 확인했다. |
| 목차 관리 회귀 | 편집, 입력 검증, 삭제, 재생성 및 실패 후 재시도 시나리오 6개가 통과했다. |

행은 `목차` 대화상자의 목록 항목 제목으로 범위를 좁혔다. 그 안의 `pdf-outline-entry`와 `현재 페이지로 설정 (3페이지)` 버튼으로 이동과 저장을 구분했다. 뷰어의 `페이지 번호` 입력란, 목차 PUT 데이터, GET으로 다시 읽은 저장본을 대조했다. 두 목차 시나리오의 미처리 페이지 오류는 0건이었다. Free 홈 스모크의 콘솔 및 페이지 오류도 0건이었다.

목차 추출·저장 테스트는 20개 통과했다. 별도 접속 URL을 요구하는 PostgreSQL 단위 테스트는 1개 건너뛰었으며, 브라우저 시나리오에서 컨테이너 DB 저장과 재조회를 확인했다. 문서 구조 검사와 변경한 브라우저 스크립트 문법 검사는 통과했다. 저장소의 i18n 검사에는 기존 `AIServersTab.tsx` 위반 8건이 있다. 운영 서버, Pro 런타임, 실서재 YES24 시나리오는 이번 검증 범위 밖이다.

`PDFIT_TEST_ORIGIN=http://127.0.0.1:15233`을 설정하고 `node apps/pdfit/tests/viewer-outline-save-page-browser.mjs` 및 `node apps/pdfit/tests/viewer-outline-management-browser.mjs`를 실행한다. 두 스크립트가 `original.pdf`를 공유하므로 관리 시나리오 전에 해당 문서의 목차를 재생성한다. 이번 실행의 JSON, 스크린샷과 트레이스는 `test/20261127/outline-current-page-headless-browser-test/`와 `test/20261127/outline-current-page-management/`에 있다. 홈 스모크 결과는 `test/20261127/outline-current-page-smoke/`에 있다.
