# 페이지 OCR 팝업 레이아웃 및 뷰어 이동 검증

2026-11-27 13:39:35 KST. Windows PowerShell, 헤드리스 Chrome, 격리된
[Free Docker](http://127.0.0.1:15385/health).

`npm run deploy:standalone`로 공유 패키지와 Free 앱을 빌드했다. 이미지
`5c55bb219999`에서 컨테이너가 `healthy`에 도달했고, `GET /health`는
HTTP 200과 `{"ok":true,"service":"pdfit"}`를 반환했다.
`/app/data/books/Fixtures`에서 생성한 PDF 두 개를 확인했다. 인덱스에도 두 개가 있었다.

| 검증 | 관측 |
| --- | --- |
| 제목과 최소 크기 | 파일명은 상단에 한 번 표시됐다. 팝업을 680px에서 400px로 줄이자 파일명 너비가 460px에서 180px로 줄고 말줄임표가 표시됐다. 상단·하단 버튼 폭은 동일했다. 최소 크기는 400 × 280 CSS px였다. |
| 페이지 이동 | PDF.js와 PDFium에서 OCR 화살표로 2쪽을 열었을 때 뷰어는 1쪽이었다. `p.2` 옆 **이동**을 누르자 뷰어가 2쪽으로 바뀌고 팝업의 위치와 크기가 유지됐다. |
| 닫기 버튼 | 한국어와 아랍어에서 헤더의 computed `padding-right`는 `5px`였고, 닫기 버튼 오른쪽 면에서 헤더 오른쪽 면까지 5 CSS px였다. |
| 하단 도구 | 하단 오른쪽에서 복사, 다시 읽기, 수정을 실행했다. 복사한 내용은 저장한 Markdown 원문과 같았고, 다시 읽기는 표시 중인 2쪽을 요청했다. 본문 머리줄의 텍스트·출처 배지와 하단 소요 시간 표기는 표시되지 않았다. |
| 좁은 화면 | 360px에서 하단 작업을 이름이 있는 아이콘으로 표시했다. 375px 모바일과 1440px 다크 화면에서 하단 버튼 세 개가 한 줄에 들어갔고 팝업과 본문에 가로 넘침이 없었다. |

두 브라우저 시나리오에서 페이지 오류와 콘솔 오류는 0건이었다. Markdown 저장,
검색 반영, 오래된 revision의 저장 거부, 책별 위치·크기 복원도 통과했다.
일반 OCR 시나리오는 디지털 PDF 탐색, 페이지 복사, 다크·모바일 단계가 통과했다.
두 시나리오의 첫 병렬 실행에서는 편집 테스트가 같은 OCR fixture를 변경해 본문 비교가
실패했다. 쓰기를 포함한 시나리오 뒤에 비교를 순차 실행해 통과했다.
5px 적용 전 격리 이미지에서 실행한 OCR 게이트웨이 복구 시나리오도 통과했다.

`node --test packages/pdfit/tests/ocr.test.mjs packages/pdfit/tests/content-search.test.mjs`
결과는 12건 통과, 1건 건너뜀, 실패 0건이었다. 건너뛴 검색 테스트는 별도
PostgreSQL 접속 URL이 필요하다. 브라우저는 텍스트 레이어 fixture를 사용했다.
패키지 문서 검사는 통과했다. i18n 공용 검사기는 기존 `AIServersTab.tsx`에서
8건을 보고했다. 변경한 OCR 카탈로그 키 두 개는 소스에서 12개 언어 값을 확인했다.
