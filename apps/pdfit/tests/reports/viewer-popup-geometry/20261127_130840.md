# Viewer popup geometry verification

## Environment

2026-11-27 13:08 KST. Windows, Docker Desktop, and Playwright Chromium. The Free instance at `http://127.0.0.1:15428` used its own Compose project, database, and two generated three-page PDFs. Source revision `2cab84d`. No external model was used.

## Results

| Popup | Minimum size (CSS px) | PDF.js | PDFGPU | Touch resize and first-tap close |
| --- | ---: | --- | --- | --- |
| Bot | 320 × 300 | PASS | PASS | PASS |
| Comments | 320 × 300 | PASS | PASS | PASS |
| Page OCR | 340 × 280 | PASS | PASS | PASS |
| Contents | 300 × 260 | PASS | PASS | PASS |

The eight desktop scenarios checked mouse movement, resize on both axes, keyboard resize, the minimum bounds, the single upper-right close button, and restoration after reopening, narrowing the viewport to 285 px, switching books, and loading a new document. The four touch cases used PDF.js with a touch-enabled 600 px viewport. Each popup shrank by 40 × 65 px and closed on the first tap after the gesture.

`npm run deploy:standalone` built the Free app and indexed two PDFs. The container reported `healthy` with zero restarts, `/health` returned HTTP 200, and both fixture files were visible inside the container. Outline and OCR tests reported 30 passed and 1 skipped. The skipped outline storage test requires an external PostgreSQL test URL. The release contract passed, and the resize label resolved for all 12 PDFit languages.

## Failures and locator outcome

A diagnostic run reproduced Chromium dropping the click after touch resize. The shared X handles a completed touch tap directly. All 12 browser cases passed after that change. The final run recorded zero page exceptions. Two console 404s came from the first GET for each fixture's stored outline. The subsequent PUTs and eight saved-outline GETs returned HTTP 200.

The scenario found the popup by its accessible name, the grip and X by their button names, and the header by its move title. OCR and Contents used the documented toolbar test IDs.
