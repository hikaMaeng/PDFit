## Defects found and fixed

1. Retry storm in the cover card. `during-backlog-before-retry-fix/cover-view.json`
   recorded 1085 responses with status 202 in one short visit and retry numbers up to
   31. The card treated `response.ok` as "ready", and 202 is also `ok`, so it reloaded
   at once instead of waiting. Fixed by testing for status 200; the browser check now
   fails when a cover is requested more than 8 times.
2. Memory kept after a batch. After the 628-task run Node held 656980 kB with the
   workers gone. Measured inside the container on 120 PDFs with 2 workers
   (`rss-experiment.txt`):

   | Setting | Peak | After the batch | Duration |
   | --- | --- | --- | --- |
   | default | 692 MB | 367 MB | 122.8 s |
   | `MALLOC_ARENA_MAX=2` | 640 MB | 365 MB | 119.6 s |
   | default, worker recycled every 20 tasks | 818 MB | 468 MB | 117.8 s |
   | `MALLOC_MMAP_THRESHOLD_=65536`, `MALLOC_TRIM_THRESHOLD_=131072` | 414 MB | 117 MB | 124.5 s |
   | both thresholds and `MALLOC_ARENA_MAX=2` | 424 MB | 124 MB | 121.1 s |

   The first hypothesis (per-thread malloc arenas) was wrong: limiting arenas changed
   nothing, and recycling workers more often made it worse. Fixed thresholds were added
   to the entrypoint's Node start line; the running process has both variables.
