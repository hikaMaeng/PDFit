## 시각 검토

- 별도 소제목, 구분선, 추가 간격 없이 태그가 연속된 한 목록으로 표시된다.
- 의미 기반 정렬은 유지되어 관련 태그가 서로 가까이 배치된다.
- 개별 태그 색상은 유지되어 기존 색상 기억과 드래그 대상 인지가 보존된다.
- 태그 삭제 아이콘은 hover/focus 때 드러나 기본 상태의 반복 시각 소음이 줄었다.
- 폴더 툴바는 선택 작업을 왼쪽, AI·폴더·보기 작업을 오른쪽에 둔 한 줄 구조로 단순화했다.
- 각 PDF의 반복 작업은 행 hover/focus 때만 보여 목록을 읽을 때의 시각 소음을 줄였다. 선택 상태에서는 체크박스만 유지한다.
- 태그 제목 오른쪽 숫자는 태그 종류 수가 아니라 모든 PDF-태그 연결 수의 합계다.
- 파일명 대신 Drive 파일 ID를 UI 식별자로 사용해 같은 제목의 PDF도 태그·선택·이동·삭제가 독립적으로 동작한다.
- 태그 작업 알림은 파란색·초록색 면을 쓰지 않고 중립적인 다크 표면으로 통일되며 상태색은 아이콘에만 제한된다.
- AI 일괄 작업 안내는 작업 중에만 툴바 아래에 표시해 가독성을 높이고 평상시 화면 밀도는 유지한다.
- 폴더 태그 해제는 관계 수만큼 개별 호출하지 않고 서버 요청 및 캐시 트랜잭션을 각각 한 번만 수행한다.
- AI 일괄 태그는 일부 PDF의 메타데이터 행이 늦게 생성된 경우에도 해당 PDF를 복구하고 나머지 배치를 중단하지 않는다.
- 1024px에서는 툴바가 제목 아래로 줄바꿈되며 PDF 목록과 겹치지 않는다.

## 로그와 실패 이력

- 15202의 새 headless 세션은 인증 정보가 없어 로그인 화면으로 이동했다. 인증을 우회하지 않고 동일 frontend의 standalone Docker 화면에서 API를 결정적으로 모킹해 검증했다.
- 첫 standalone 실행은 기존 NAS 외부 볼륨 연결 거부로 실패했다. 사용자 서재를 건드리지 않기 위해 `pdfit-ui-test-books` 테스트 전용 볼륨으로 재실행했다.
- Python Playwright 모듈이 번들 런타임에 없어 저장소에 이미 고정된 Node Playwright로 전환했다.
- 의도적으로 재현한 폴더 태그 해제 500 응답 외에 제품 코드에 해당하는 브라우저 오류는 없었다.
