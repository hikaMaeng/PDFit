# Book Bot production retry

The user report and the first local retry both ended when Docker stopped the Free container. The second local retry reused the same real book, OCR index and diagnostic session.

| Time (KST) | Event |
|---|---|
| 19:17:53 | Nginx reported that the PDFit upstream closed the Bot SSE request early. Docker sent a stop signal to the Free container in the same second. |
| 19:27:10 | Docker sent a stop signal while a headless Chrome retry was reading the same question's HTTP 200 event stream. Chrome lost the response. |
| 19:27:32 | Docker started the replacement Free container. |
| 19:28:48 | The same question began page selection in the replacement container. |
| 19:30:05 | OCR loaded and the answer model started. |
| 19:33:45 | The viewer received the model's thinking stage. |

The second headless Chrome run passed against `http://127.0.0.1:15203`. The viewer opened the same 404-page book and sent the same Korean chapter-four question. It received the first answer fragment at 19:34:38, 5 minutes 52 seconds after submission. The full turn took 6 minutes 50 seconds and produced 1,479 fragments followed by a `saved` event. The conversation log showed the answer, the session API returned the same saved turn, and Chrome reported no page errors. PostgreSQL recorded 33 OCR pages from PDF pages 128–160. The container remained healthy.

This run followed the [page selection test plan](../../plans/book-bot-page-selection-20261127.md) with the actual library and configured Qwen server. The public host's authenticated repro was identified in the Nginx logs. The browser verification used the running container's published loopback port. A container replacement can still interrupt an open response.

Artifacts in `test/20261127/192248_book-bot-live-retry/` include `interrupted-result.json`, `live-browser.log`, `result.json`, `saved-scope.json` and `book-bot-answer.png`.
