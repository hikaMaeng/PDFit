# Book Bot의 책 범위 벡터 검색

Free Bot은 제목, 원본 목차, 세션 기록과 사용자 질의로 검색 문구를 만든다. PostgreSQL은 현재 책의 폴더와 파일명이 같은 레코드만 벡터로 비교한다. 답변 모델은 검색 결과를 도구 결과로 받고 마지막 사용자 메시지의 질의에 응답한다. [검증 계획](../../plans/book-bot-page-selection-20261127.md)

2026년 11월 28일 12시(KST)에 포트 15384의 격리 Free에서 pgvector와 모의 AI 공급자로 검증했다. 테스트에서 목차상 4장 범위는 8–21쪽이었다. 벡터에 가까운 30쪽 OCR이 첫 결과였고 같은 책의 코멘트가 그다음이었다. 벡터 점수가 더 높은 다른 폴더의 동명 PDF와 같은 폴더의 다른 PDF는 모두 제외됐다. 이전 리비전의 12쪽도 결과에 없었다.

API 테스트는 원본 목차, 도구 호출과 도구 결과의 ID, 마지막 사용자 메시지, 응답 스트림과 세션 복원을 확인했다. 대화만 묻는 후속 질의는 임베딩 호출을 건너뛰었다. Headless Chrome에서 진행 상태, 첫 응답 조각, 새로고침 뒤 답변 표시를 확인했다. 페이지 오류는 없었다. AI·OCR·색인 회귀 테스트 27개와 Free 빌드, 릴리스 소스 계약 검사도 통과했다.

운영 Free는 스캔과 AI 연결이 정리된 뒤 `npm run deploy:standalone`으로 재배포했다. 백업에 기존 테이블이 포함됐는지 확인했다. 배포 전후 책 759권과 목차 10개, OCR 850쪽, 클립 3개, 코멘트 2개의 수가 일치했다. Bot 세션 4개와 질의응답 3개의 수와 대화 해시도 같았다. Docker와 루프백·LAN HTTP 상태가 정상이었다. 운영 Bot·검색 모듈 5개의 해시가 빌드 산출물과 일치했다. APIBond에 이미 등록된 `embeddinggemma2:mp`를 기본 임베딩 모델로 선택해 운영 색인을 시작했다.

12시 22분 기준 색인에 벡터 조각 3,019개가 저장됐다. 검증 대상 책의 OCR 404쪽 중 148쪽, 4장 범위 33쪽 중 11쪽이 벡터 검색에 열렸다. 첫 주기의 처리량에 도달해 원본 503건은 대기열에 남았다. 서재의 의미 검색 API도 같은 모델로 페이지 OCR 결과 3건을 반환했다.

운영 브라우저에서 새 테스트 세션을 열고 4장의 실행 추적기가 무엇을 기록하고 왜 필요한지 두 문장으로 물었다. Qwen은 기록 대상과 디버깅·성능 분석 용도를 답하고 PDF 150–151쪽을 인용했다. 인용한 두 쪽은 모두 세션에 저장된 벡터 근거 12쪽에 포함됐다. 목차에서 고른 페이지 키는 비어 있었고 복원한 세션의 원본 목차에는 201개 항목이 있었다. 브라우저는 답변 조각 77개를 받았으며 저장된 답변을 다시 열었다.

운영 요청은 6분 18초 걸렸다. 임베딩 워커 대기는 약 0.9초였다. 워커 배정부터 검색을 마치고 답변 모델을 호출하기까지 약 0.3초가 걸렸다.

원본 로그와 브라우저 캡처는 `test/20261128/120145_book-bot-vector/`에 있다. 격리 브라우저 기록은 `integration-rerun.log`와 `browser/`, 회귀 테스트는 `unit.log`와 `rollover-postgres.log`, 운영 결과는 `live-verification.json`, `active-embedding.json`, `live-browser/`에 저장했다.
