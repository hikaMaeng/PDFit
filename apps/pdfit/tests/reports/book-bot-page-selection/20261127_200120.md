# Book Bot answering after retrieval

The reported production turn stored a 2,993-character answer headed by section 4.1. Its 33 OCR pages entered the answer model as evidence. The router sent the answer model's deltas to the browser, and kept the planner's selection and page bodies out of the stream.

The first revision put the reader's question after a JSON reference message. In a real Qwen3.6 run on the same book and question, the model returned a 4,819-character section-by-section digest. A question asking why the chapter separated planning and execution received two sentences with citations to pages 132 and 158. The planner selected 33 OCR pages for the chapter request and seven for the design question.

The next revision used a matched assistant tool call and tool result. To hold the sources constant, the test replayed the earlier selections and called the actual answer model. The chapter request returned 3,606 characters. It opened with an overview, then recited the sections, function list, exercises and bibliography. The design question received two sentences and cited page 158.

The final revision records the completed lookup in a tool result, then repeats the reader's request as the final user message. The wire contract saves one turn and streams only the final answer. The build and 19 AI/OCR regression tests passed. The isolated Free test on port 15383 checked the two model inputs, tool call ID, exact trailing question, two summary rollovers, streamed fragments, idempotent replay, and restored conversation. Headless Chrome reported no page errors.

The final real-model replay used the same 33 OCR pages and verified the full request after the tool result. It returned 2,107 Korean characters in 978 answer fragments. The opening paragraph states what the chapter builds and what the engine does. The body still follows the section order and lists implementation details. The response omitted PDF page citations. The answer replay took 8 minutes 28 seconds with the planner output supplied by the test.

Free was deployed through `npm run deploy:standalone` after checking for active scan jobs and open AI connections in that container. The answer module in production matched the browser fixture build. Docker, loopback HTTP and LAN HTTP were healthy. The pre-deploy database dump was readable. Before and after the deploy, the counts were 745 books, nine outlines, 440 indexed OCR pages, three clips, two comments, three Bot sessions and two turns. The transcript checksum also matched.
