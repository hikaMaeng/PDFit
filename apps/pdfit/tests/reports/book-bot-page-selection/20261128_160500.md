# Book Bot의 도구 호출 표기 노출 수정

운영에서 《에이전틱 디자인 패턴》의 단일 프롬프트 한계를 설명해 달라는 대화를 확인했다. PostgreSQL에는 벡터 검색으로 고른 OCR 12쪽과 텍스트 `<tool_call>…</tool_call>`이 답변으로 저장돼 있었다. 검색 이후 답변 요청에 넣던 가상 도구 호출 이력을 제거했다. 답변 모델은 사용자 메시지에서 검색 근거를 읽고 그 끝에 있는 원래 질문에 답한다.

AI·OCR 회귀 테스트 23개와 Free 빌드, 릴리스 소스 계약 검사를 통과했다. 격리 Free에서는 모의 공급자가 도구 호출 표기를 세 개 이상의 SSE 조각으로 나눠 보냈다. 응답은 502였으며 화면에 보낸 답변 조각은 0개였다. 새 답변은 저장되지 않았다. 과거에 저장된 호출 표기는 브라우저에서 재시도 안내로 표시됐다. 질문과 DB 원본은 그대로 남았다. 정상 답변은 스트리밍되고 새로고침 뒤에도 표시됐다.

운영 백업을 별도 PostgreSQL에 복원하고 서재 볼륨을 읽기 전용으로 붙였다. 복제본에서 같은 책과 같은 질문을 실제 APIBond 모델에 보냈다. 브라우저 제한 시간인 10분 동안 분석 단계에 머물렀으며 답변 조각과 저장된 답변은 없었다. 복제본에서 유휴 백엔드도 확인했으나 APIBond가 해당 모델 풀에 속하지 않는다며 409를 반환했다. 실제 모델의 답변 생성은 확인하지 못했다.

16시 27분(KST)에 운영 배포 조건을 확인했다. 현재 책의 스캔은 508쪽 중 168쪽을 처리했고 4쪽이 실행 중이었다. 운영 컨테이너를 재시작하면 스캔이 끊기므로 배포를 보류했다.

[검증 계획](../../plans/book-bot-page-selection-20261127.md). 증거는 `test/20261128/160500_book-bot-tool-markup/`에 저장했다. `rebased-unit.log`와 `integration-rerun.log`에 테스트 결과가 있다. `browser/invalid-saved-reply.png`와 `browser/first-delta.png`는 과거 실패 안내와 정상 스트리밍을 기록했다. 실제 모델 시도는 `real/browser.log`와 `real-idle/provider-probe.json`에 남겼다.

## 운영 배포

2026년 11월 28일 19시 32분(KST)에 `c5a1fdc`를 Free에 배포했다. `npm run deploy:standalone`과 배포 전후 검증에 112.7초가 걸렸다. Docker 상태는 `healthy`였고 루프백과 LAN의 15203번 포트에서 `/health`가 성공했다. 외부 주소의 비인증 요청은 Basic 인증을 요구하는 401을 반환했다.

배포 전 PostgreSQL을 백업했다. 책 759권과 OCR 946쪽, 벡터 조각 4,908개, Bot 세션 6개, 질의응답 5개의 수가 일치했다. 대화 체크섬과 기본 임베딩 설정도 같았다. 서재 볼륨을 컨테이너 안에서 읽었고 Bot·임베딩 모듈 4개의 해시가 빌드 산출물과 일치했다.

운영 브라우저에서 문제의 대화를 다시 열었다. 질문이 표시됐고 기존 호출 표기는 재시도 안내로 표시됐다. 데이터베이스에는 원본이 남았다. 이번 브라우저 검증 범위는 기존 대화 복원이다. 재배포 빌드로 실행한 AI·OCR 회귀 테스트 23개가 통과했다.

종료된 테스트 컨테이너 4개와 병합된 Bot 작업 브랜치를 제거했다. Bot 검증 자료를 주 저장소의 `test/`로 옮겼다. 스캔 작업 트리의 미커밋 변경과 Docker 볼륨은 보존했다. 배포 증거는 `test/20261128/192835_free-deploy/`의 `verification.json`, `browser.json`, `book-bot-history.png`, `unit.log`에 있다.
