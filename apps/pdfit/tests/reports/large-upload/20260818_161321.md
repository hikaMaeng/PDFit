# Test Report: large PDF upload

## Timestamp

2026-08-18 16:13:21 KST

## Environment

- Windows 11
- PDFit 0.4.3
- Docker Compose `pdfit` service
- Chromium via Playwright
- Runtime `MAX_UPLOAD_MB=2048`

## Root cause

The upload middleware had a hard-coded 200 MiB per-file limit. Multer reported
`LIMIT_FILE_SIZE`, but the route forwarded it to the default error handler as
HTTP 500. The browser maps completed network transfer to 70%, so this appeared
as a stalled 70% upload.

## Steps and results

1. Raised the default per-file limit to 2048 MiB: passed.
2. Added validated 1–10240 MiB runtime configuration: passed.
3. Added explicit HTTP 413 handling for configured-limit violations: passed.
4. Built shared, Docker, and hosted-service variants: passed.
5. Rebuilt and recreated the Docker service: passed.
6. Uploaded a 201 MiB fixture through Chromium's real file input: HTTP 200.
7. Deleted the uniquely named server fixture and local test fixture: passed.
8. Ran `verify:repo`, `verify:pdfit`, and `verify:service-parity`: passed.
9. Inspected the deployed `이북` page and confirmed only the user's two PDFs remain: passed.
