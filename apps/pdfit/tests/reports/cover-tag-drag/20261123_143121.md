# 표지 카드 태그 드래그 검증

- 실행 환경은 2026-11-23 14:26~14:33 KST, Windows, Chrome 157.0.8103.79, Free Docker `http://127.0.0.1:15203`이다. [테스트 계획](../../plans/cover-tag-drag-20261123.md)
- 수정 전 `4bd070e` 배포본에서 목록 제목과 마우스를 올린 표지 드래그는 통과했다. 상세 정보가 고정된 표지에서는 드롭 후 태그 추가 요청이 발생하지 않았다.
- `npm run deploy:standalone`이 64.31초에 완료됐다. Free 컨테이너는 `healthy`, `/health`는 HTTP 200을 반환했다. 컨테이너의 `BOOKS_ROOT`와 라이브러리 인덱스에서 각각 PDF 719개를 확인했다. `npm run verify:release-contract`도 통과했다.
- `node apps/pdfit/tests/cover-tag-drag-browser.mjs`는 목록 제목, 마우스를 올린 표지, 상세 정보가 고정된 표지, 카드 제목에서 실제 마우스 드래그를 실행했다. 네 경로 모두 지정한 책의 태그 추가 POST 200, 대상 행 개수 증가, 대상 태그 화면의 문서 표시를 확인했다. 페이지 오류는 없었다. 태그 API 응답은 테스트에서 제공했다.
- 읽기 전용 `free-cover-view-deployed-browser.mjs`는 `PDFIT_FOLDER=AX`에서 표지 4개 HTTP 200, 너비 360px, 원본 PDF 요청 0건으로 통과했다. 기본 `이북` 폴더에서는 360px 검사에 실패했다. 해당 표본에는 360px 자동 표지와 `c` 쿼리로 구분되는 879~959px 교체 표지가 섞여 있었다.
- 브라우저는 `pdf-cover-media`에 포인터를 올린 뒤 `pdf-cover-info-overlay`의 버튼과 태그 칩 아래에서 드래그를 시작했다. 제목은 파일명 링크, 대상은 `lnb-tag-row`의 정확한 태그 이름으로 찾았다.
- 스크린샷은 `test/20261123/142604_headless-browser-test/`의 `before/`, `after/`, `live/`에 저장했다. Pro와 터치 입력은 검증 범위 밖이었다.
