## 첫 적용 범위

첫 적용은 Free로 잡는다. 원문 조회, PostgreSQL 저장, 큐와 검색은 `packages/pdfit`이 맡는다. Free의 AI 설정과 라우터 연결은 `apps/pdfit`에 둔다. Pro 적용에는 계정별 원문·검색·삭제를 공용 로직과 연결하는 별도 설계가 필요하다.

| `ref` | 원문 | `refid` |
| --- | --- | --- |
| `book_page_ocr_search` | 현재 파일 버전과 맞는 페이지 텍스트. OCR·텍스트 레이어·사용자 수정 포함 | `[folder, filename, page_index]`를 고정 형식으로 직렬화한 복합 키 |
| `bookmarks` | `ocr_status = 'done'`일 때 `ocr_text`, 클립 코멘트 `comment` | 클립 UUID. 내부 출처 키에 `ocr_text` / `comment` 포함 |
| `book_comments` | 일반 코멘트 `body` | 코멘트 UUID |

빈 텍스트와 이미지 전용 코멘트는 색인에서 뺀다. 페이지 OCR은 파일 크기·수정시각 검사를, 클립과 코멘트는 현재 책의 존재 검사를 재사용한다. 목차와 제목은 기존 키워드 검색 범위다. 키와 페이지 연결 규칙은 [현재 검색 코드](../packages/pdfit/src/server/postgres/contentSearch.ts)와 [일반 코멘트 저장소](../packages/pdfit/src/server/postgres/bookComments.ts)를 기준으로 삼는다.

## AI 서버와 기본 모델

1. AI 서버별로 등록된 LLM과 임베딩 후보를 설정 화면에서 보여 준다. 현재 서버별 역할당 하나인 매핑을 후보 목록으로 확장한다. 비전 모델은 기존 설정을 쓴다. 기본 LLM과 기본 임베딩은 PDFit 전체에 각각 최대 하나다. 역할별로 서로 다른 서버를 고를 수 있다. 선택값은 모델 레코드 ID로 저장한다.
2. 임베딩 후보에는 모델명, 기본 차원, 인덱스 차원, 임베딩 동시성을 명시한다. 화면의 동시성 설명에는 `한 요청에 담을 최대 텍스트 수`라고 적는다. 모델별 최대 입력 토큰과 배치 한도, 문서·질의 입력에 필요한 프리픽스는 모델별 입력 계약으로 관리한다. 임의 이름의 호환 모델도 입력 계약을 확인한 후 활성화한다.
3. 기존 설정은 역할별 후보로 옮긴다. 명시 선택 전에는 현재 첫 유효 LLM과 자동 태그의 `SERVICE_AI_*` 우선순위를 이행 모드에서 보존한다. 레거시 임베딩에는 미설정 상태를 표시한다. 입력 계약을 채우고 기본값으로 선택하면 색인을 시작한다.
4. 첫 명시 선택부터 Book Bot, 화면 번역, Free 자동 태그, 비전 모델 미등록 시 OCR 대체 경로가 같은 기본 LLM을 조회한다. `SERVICE_AI_*`는 이행 모드에서만 자동 태그 설정에 적용한다. 기본값을 해제하면 이를 명시적으로 저장해 이행 모드가 다시 켜지지 않게 한다. 필요한 LLM이 없으면 각 기능이 설정이 필요하다고 응답한다.
5. 화면에 역할별 기본 모델과 서버를 표시한다. 활성 임베딩의 모델명·엔드포인트·차원 변경은 새 프로필을 검증하고 전환하는 절차로 처리한다. 활성 후보나 서버 삭제 시 다른 후보를 지정하거나 기본값을 해제해야 한다. 차원과 배치 수는 UI와 API 양쪽에서 검증한다. 설정 화면에는 임베딩 원문을 선택한 서버로 보낸다는 점을 안내한다.

## 모델별 검색 테이블

기본 임베딩을 고르면 테스트 문구 배열로 `/embeddings` 요청과 응답 차원을 검증한다. 모델 ID와 배포를 구분하는 프로필에는 서버 식별자, 모델명과 배포 리비전, 차원, 문서·질의 입력 계약, 청킹 버전을 포함한다. 같은 모델 별칭으로 가중치를 바꿀 때는 배포 리비전을 올려 새 테이블을 사용한다. 배치 크기만 바꾸면 기존 색인을 재사용한다.

물리 테이블명은 `emb_<model_slug>_<hash>`로 만든다. 원래 모델 이름과 물리 이름을 레지스트리에 보관한다. 물리 이름은 ASCII 63바이트 이하로 제한하고 레지스트리에서 검증한 식별자만 SQL에 사용한다. 동일 물리 이름에 다른 프로필이 연결되면 충돌로 처리한다. [PostgreSQL 식별자](https://www.postgresql.org/docs/17/sql-syntax-lexical.html)

요청 검증은 DB 트랜잭션 밖에서 한다. 검증을 시작할 때 선택 요청 토큰과 후보·서버 연결 버전을 읽는다. 활성화 직전에 잠금 아래 다시 확인한다. 서버의 URL·헤더가 바뀌거나 후보가 지워지거나 새 선택 요청이 들어오면 기존 검증 결과를 폐기한다. 헤더 변경으로 다른 배포를 가리키면 새 프로필로 검증한다. 같은 배포의 자격 증명만 교체한 경우에는 재검증 후 기존 색인을 쓴다.

같은 트랜잭션에서 모델 테이블의 열 타입·차원·인덱스 상태를 확인한다. 최초에는 빈 테이블과 인덱스를 만든 뒤 기본값과 활성화 세대를 기록한다. 데이터가 든 테이블의 대규모 인덱스 복구는 백그라운드에서 마친 뒤 활성화한다. 요청 검증과 DDL에는 각각 제한 시간을 둔다. 실패하면 현재 선택을 유지한다. 기동은 정적 스키마 확인과 설정 읽기까지만 한다.

| 필드 | 저장 값 |
| --- | --- |
| `id` | 청크와 원문 리비전을 구분하는 키 |
| `contents` | 원문에서 잘라낸 청크. 모델 프리픽스는 제외 |
| `ref` | 원본 테이블명 |
| `refid` | 원본 레코드 키 |
| `embedding` | 모델 기본 차원의 `vector(D)` |
| `hnsw` | 인덱스 차원의 `vector(d)` 및 `vector_cosine_ops` HNSW |

청크 순번·원문 범위·필드 구분·리비전과 발행 상태는 별도 메타데이터에 둔다. 청크 ID에 필드 구분을 반영해 클립 OCR과 코멘트가 같은 UUID를 공유해도 덮어쓰지 않는다. `vector` HNSW에는 `1 ≤ d ≤ min(D, 2000)`을 적용한다. `D`는 설치된 pgvector의 저장 한도 안에서 검증한다. `d < D`이면 모델이 그 차원의 MRL prefix를 지원하는지 확인한 뒤 앞의 `d`개 값을 사용한다. 질의와 문서에 같은 인덱스 변환을 적용한다. MRL을 지원하지 않는 모델은 기본 차원과 인덱스 차원을 같게 설정한다. [pgvector](https://github.com/pgvector/pgvector#hnsw) · [Matryoshka Representation Learning](https://proceedings.neurips.cc/paper_files/paper/2022/hash/c32319f4868da7613d78af9993100e42-Abstract-Conference.html)

## 책 본문 청킹

- 페이지를 원문 단위로 삼아 문단·문장 경계에서 나눈다. 긴 문장이나 줄바꿈 없는 OCR도 토큰과 유니코드 경계에 맞춰 분할한다. 모델별 토크나이저로 프리픽스·특수 토큰을 포함한 입력 토큰 수를 셈한다. 목표 512토큰, 겹침 64토큰으로 시작해 모델 한도와 검색 품질에 맞춰 조정한다. 코멘트와 클립도 같은 분할기를 사용한다. 분할 작업은 처리할 원문 바이트와 시간을 제한한다. 페이지 한 장이 길면 진행 위치와 겹칠 문맥을 다음 작업에 넘긴다.
- 현재 키워드 색인은 `body`를 먼저 64,000 UTF-16 코드 단위로 자른 뒤 NUL을 제거한다. 레거시 `body`의 길이만으로 전체 원문인지 판별할 수 없다. OCR 저장과 수동 수정 시 같은 출처 행에 임베딩용 전체 텍스트와 리비전을 반영한다. 키워드용 GIN의 범위는 그대로 둔다. 원문 리비전은 잘린 `body`와 별개로 전체 텍스트 변경을 감지한다. PostgreSQL이 저장할 수 없는 NUL은 원문 투영 규칙에서 처리하고 위치가 바뀌지 않게 한다. [현재 페이지 OCR 투영](../packages/pdfit/src/server/postgres/contentSearch.ts)
- 기존 원문은 파일 버전과 페이지에 맞는 전체 OCR 캐시에서 복원한다. 전체 원문을 입증할 캐시가 없으면 기존 `body`에서 남아 있는 텍스트를 부분 색인한다. 상태에 전체 원문 미확보를 표시하고 기존 OCR 복구 경로로 연결한다. 부분 원문과 전체 원문에 서로 다른 리비전을 쓰며 전체 원문을 확보하면 다시 색인한다. 기존 DB 키에서 캐시를 직접 찾는 작업과 캐시에만 존재하는 페이지를 찾는 작업을 공용 풀에서 실행한다. 첫 계획의 전체 `readdir`·전체 책 목록 조회를 제한된 디렉터리 탐색과 키 조회로 옮긴다. 재기동 때 탐색을 다시 열어도 파일별 확인 상태로 완료한 쓰기를 건너뛴다. [캐시 복원](../packages/pdfit/src/server/ocr/pageOcrSearchIndex.ts)
- 캐시와 DB는 별도 쓰기다. 페이지별 저장 순서와 파일 버전·텍스트 리비전 검사를 재사용한다. 복원 전에 읽어 둔 캐시로 새 수동 수정을 덮어쓰지 않도록 DB 쓰기 직전 캐시 리비전과 기대 DB 리비전을 확인한다. 캐시 교체 직후 중단되거나 DB 저장이 실패해도 다음 복원에서 불일치를 찾아 처리한다. [페이지 OCR 저장 경로](../packages/pdfit/src/server/ocr/ocrService.ts)
- 청킹 규칙은 모델 프로필에 버전을 기록한다. 모델 입력을 정규화해도 `contents`에는 원문 조각을 보관한다. 위치는 출처 키, 청크 순번과 원문 UTF-16 범위로 기록한다. 검색 화면은 그 위치로 페이지 또는 클립·코멘트를 연다. 겹치는 결과는 같은 출처 안에서 묶는다.

## 시간별 차이 계산과 전용 큐

1. 기존 `TaskScheduler`에 임베딩용 `PeriodicTaskDefinition`과 스크립트를 등록한다. 매시간 `plan()`은 활성 프로필과 처리할 작업의 유무를 확인해 시작 작업 하나를 넣는다. 무거운 캐시 해석·토큰 계산·응답 해석은 공용 풀에서 작은 작업으로 실행한다. 네트워크 대기는 슬롯과 DB 연결을 반환한 뒤 비동기 디스패처에서 처리한다. [스케줄러 등록부](../packages/pdfit/src/server/bootstrap/createCommonRouters.ts)
2. 원문 변경 트랜잭션에서 출처별 최신 리비전과 대기 표식을 기록한다. 원본별 트리거의 `OLD`·`NEW` 키로 삽입·본문 수정·삭제를 잡는다. 책 삭제와 파일 무효화, 외래 키로 이어지는 이동, `bookmarks`의 명시적 이동, OCR 완료에서 `pending`으로 돌아가는 경우도 포함한다. 시간별 작업은 이 키를 활성 모델의 발행 상태와 우선 비교한다. 초도 색인과 누락 확인에는 출처별 인덱스를 쓰는 keyset 탐색과 색인에서 원문을 역조회하는 탐색을 사용한다. 각 출처와 삭제 처리에 일정 몫을 둬 대량 백필이 최근 변경을 밀어내지 않게 한다.
3. 삽입·내용 변경은 영속 큐에 넣고 삭제와 빈 본문은 API 호출 없이 검색에서 제외한다. 큐에는 프로필·출처 키·기대 리비전·진행 위치·재시도 시각을 저장한다. 큐 등록과 커서 전진, `WHERE revision = observed` 조건을 적용한 대기 표식 해제는 같은 트랜잭션으로 묶는다. 최신 수정의 표식은 보존된다. 큐가 차면 등록하지 못한 분량부터 이어 간다. 활성 프로필이 없어도 기존에 색인한 모델의 삭제·수정 원문은 정리 대상에 남는다.
4. 스케줄러가 실행 키를 해제한 뒤에만 같은 키의 후속 실행을 제출한다. 현재 `onSettled` 안에서는 그 키가 아직 실행 중이다. 실행 해제 후 알림과 공용 큐 공간이 생겼을 때의 재제출을 기존 스케줄러에 연결한다. 보류 신호는 작업 종류당 하나로 합친다. 계획 교체·큐 포화·재기동 때는 PostgreSQL의 다음 작업을 다시 조회한다. 재시도 시각까지 기다려야 할 때는 기존 스케줄러의 후속 기회나 다음 시간별 계획을 사용한다. [실행 키와 계획 교체 로직](../packages/pdfit/src/server/tasks/taskScheduler.ts)
5. Free의 단일 서버 프로세스에서 백필·검색·모델 검증 요청이 임베딩 디스패처 하나를 공유한다. 한 번에 요청 하나를 전송하며 설정한 base URL에 `/embeddings`를 붙인다. 백그라운드 배치는 `embeddingConcurrency` 이하 청크를 `input: [...]`로 묶는다. 개별·합계 토큰과 요청·응답 바이트에 별도 상한을 둔다. `data[].index`로 결과를 대응시키고 누락·중복·범위·차원을 확인한다. 원본과 MRL 양쪽 벡터에서 float32 범위를 벗어난 값, 비유한값, 코사인 거리를 계산할 수 없는 0벡터를 거절한다. 진행 중인 배치가 끝나면 대기 중인 사용자 검색을 우선한다. 대기열 크기와 대기·요청 시간에 한도를 두고 검색 취소를 전달한다. 동일 장치의 OCR·LLM 지연도 같이 측정한다. [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)
6. 배치 예약에 만료 기한과 실행 토큰을 부여한다. 재시도할 때 같은 청크를 멱등 저장한다. 발행 트랜잭션은 활성 설정, 원문 리비전, 작업 예약 순서로 잠근다. 잠금 아래 활성화 세대와 리비전, 실행 토큰을 다시 확인한다. 마지막 청크가 저장되면 완료 표시를 바꾼다. 검색은 완료 표시와 현재 원문 리비전이 맞는 청크를 읽는다. 수정·삭제·전환보다 늦게 도착한 응답은 폐기한다. 이전 청크는 작은 삭제 단위로 걷어 낸다.
7. 원격 장애와 `429`는 대기 시간을 둬 재시도한다. `Retry-After`가 있으면 반영한다. 길이·입력 오류는 배치를 나눠 실패 입력을 좁힌다. 잘못된 프로필이나 인증 실패는 반복 호출을 멈추고 상태를 표시한다. `GET /api/tasks/status`는 저장한 대기·재시도·색인 진척·원문 미확보·최근 오류를 읽는다. 상태 요청에서 전체 건수를 스캔하지 않는다. 본문과 인증 헤더는 로그에서 제외한다.

초기 실험값은 조회 최대 100행, 임베딩 실행 슬롯 한 개다. 행 수와 별도로 DB 시간·초당 쓰기량·원문 읽기 바이트·실행당 토큰·시간별 배치 수를 제한한다. 작업 사이에 슬롯을 반납하며 시작 지연은 기존 설정을 따른다. 키워드 검색·뷰어·OCR 지연과 전체 색인 완료 시간을 함께 측정해 한도를 조정한다.

## 검색과 모델 전환

기존 `/search`에 의미 검색 모드를 추가한다. 주소에 모드와 선택한 출처를 보관한다. `POST /api/search/semantic`에 `q`·출처·`limit`을 넘긴다. 페이지 OCR은 뷰어의 원래 페이지, 클립은 기존 UUID 링크, 일반 코멘트는 코멘트 UUID를 지정한 대화상자로 연다. 코멘트 위치 조회는 책과 UUID를 함께 검증하며 전체 코멘트를 읽어 위치를 찾지 않는다. 입력이 바뀌거나 모드를 닫으면 요청을 취소하고 늦은 응답을 버린다. 모델 미선택·색인 중·장애를 화면에 표시한다. 기존 키워드 검색도 같은 화면에서 이용한다. [검색 화면](../packages/pdfit/src/front/pages/SearchPage.tsx) · [현재 결과 연결](../packages/pdfit/src/front/pages/ContentSearchResults.tsx)

기본 차원의 질의 벡터를 만들고 `hnsw` 코사인 거리로 후보를 고른 뒤 `embedding`으로 다시 순위를 매긴다. 필터에 걸린 미완료·폐기 리비전과 같은 출처의 중복이 후보를 채울 수 있다. 실제 `vector` 확장 버전을 확인해 가능한 경우 제한된 반복 스캔을 사용한다. 그 밖에는 후보 창을 정해진 상한 안에서 늘리며 이미 찾은 행을 중복 처리하지 않는다. 원본 차원 exact 검색은 작은 범위의 보완과 검증 기준에 쓴다. 후보 탐색량과 DB 시간에 상한을 둔다. 모든 경로에서 현재 출처 및 발행 상태를 확인한다. [pgvector 필터와 반복 스캔](https://github.com/pgvector/pgvector#filtering)

활성화 세대를 바꾸면 검색과 새 작업이 함께 이동한다. 모델을 다시 선택하면 현재 원문 리비전과 일치하는 벡터부터 재사용한다. 전환 중 시작한 검색도 응답 전 세대를 확인한다. 비활성 테이블에 남은 수정 전 원문과 삭제 원문은 작은 단위로 정리한다. 정리 대상 모델의 진행 위치를 남겨 활성 모델 전환이나 큐 포화가 삭제 확인을 건너뛰게 하지 않는다.

## 구현과 검증 순서

| 단계 | 작업과 통과 조건 |
| --- | --- |
| 1 | 후보와 기본 모델, 레지스트리·테이블 생성. 기존 설정과 `SERVICE_AI_*` 이행, 동명 모델/배포 교체, 동시 선택, 검증 중 PATCH·DELETE, 역순 검증 응답, DDL 실패를 확인한다. 명시한 기본 LLM이 네 호출 경로에 적용되어야 한다. |
| 2 | 원문 조회·복원과 청킹. 64,000 이후만 바뀐 페이지, NUL이 든 잘린 레거시 원문, 캐시에만 있는 페이지, 캐시 교체 직후 DB 실패·재기동, 복원과 수동 수정 경합을 검증한다. 부분 색인에서 전체 색인으로 복구할 때 장문 끝 문구가 검색되어야 한다. 한·영·이모지 경계, 텍스트 레이어, 클립의 두 필드와 이미지 전용 코멘트도 확인한다. |
| 3 | 차이 계산·영속 큐·배치 발행. 실제 요청 기록에서 최대 동시 요청 1건, 배열 크기와 바이트 한도를 확인한다. 공용 슬롯 1개에서 모델이 지연되는 동안 OCR이 진행되어야 한다. 계획 교체·포화에도 한 주기 안에서 배치가 이어지고 중단 뒤 복구되어야 한다. 대기 표식 해제 직전 수정, 발행 직전 삭제, 책 이동·무효화·같은 경로 재생성, 비활성 중 삭제 후 A→B→A에서 과거 원문이 검색되지 않아야 한다. |
| 4 | 의미 검색과 UI. 네 출처의 정답 질의와 원본 링크, 색인 중·장애 표시, 검색 취소와 모드 전환을 브라우저와 PostgreSQL에서 검증한다. 미완료·폐기 행과 중복 청크가 많은 경우를 포함해 원본 차원 exact 검색 대비 recall@k와 시나리오별 응답 시간을 기록한다. |
| 5 | Free 규모 검증. 현재 규모 및 증가한 규모의 합성 데이터에서 최초 구축과 시간별 소량 변경을 측정한다. 기동/health, 검색·뷰어·OCR 응답 p95, DB I/O, 메모리·이벤트 루프 지연, 큐 회복 시간과 디스크 증가량을 기능을 켠 경우와 끈 경우에 각각 기록한다. 기준선 측정 뒤 허용 지연과 시간당 적정 처리량을 정한다. 배포 검증에서 실제 pgvector 버전, Docker health와 브라우저 증거를 확인한다. |

## 독립 리뷰에서 바꾼 내용

대화 이력 없이 요구사항과 관련 소스 경로를 전달한 서브에이전트가 초안을 읽었다. OCR 원문 입증과 캐시 복원, 스케줄러 재제출, 변경·발행 경합, 모델 검증·선택 경합, 환경 변수 우선순위, 검색 연결과 ANN 후보 부족을 지적했다. 각 항목을 설계와 검증 조건에 반영했다.
